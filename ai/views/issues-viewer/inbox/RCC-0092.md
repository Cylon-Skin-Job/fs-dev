Research session concluded on the correct implementation approach for each macOS connector in Chunk F. Several SPECs need updating to reflect read-only vs write paths and the native API landscape.

**Depends on:** RCC-0087 (Chunk F — macOS Connectors Panel)

---

## Research Conclusions

### 1. Apple Notes
- **Direct SQLite** (`~/Library/Group Containers/group.com.apple.notes/NoteStore.sqlite`):
  - Metadata (titles, folders, dates, snippets) is easily queryable.
  - Note body (`ZICNOTEDATA.ZDATA`) is a **gzip-compressed proprietary binary blob**.
  - Schema is undocumented CoreData — changes between macOS versions.
- **AppleScript** (`tell application "Notes"`) returns clean text/HTML.
- **Recommendation:** Use **AppleScript** for Notes connector. Requires **Automation TCC** (`kTCCServiceAppleEvents`).

### 2. Apple Reminders
- **Direct SQLite** (`~/Library/Group Containers/group.com.apple.reminders/Container_v1/Stores/Data-*.sqlite`):
  - Readable CoreData schema (`ZREMCDREMINDER`, etc.).
  - **Fragile** — Apple explicitly designed EventKit to mediate access for sync safety.
  - Bypassing EventKit risks corruption and breaks iCloud sync.
- **EventKit** (`EKReminder`) is the **official API**.
  - ~3000× faster than AppleScript.
  - Handles iCloud/Exchange sync correctly.
  - Built-in change notifications (`EKEventStoreChangedNotification`).
- **Recommendation:** Use **EventKit** for Reminders. Requires **Reminders TCC** (`kTCCServiceReminders`).

### 3. Apple Mail
- **Direct SQLite** (`~/Library/Mail/V10/MailData/Envelope Index`):
  - Excellent for **read-only** bulk sync — 1400× faster than AppleScript.
  - Rich schema: `messages`, `mailboxes`, `subjects`, `senders`, `recipients`, `attachments`, `conversations`, `searchable_messages` (FTS5).
  - Message bodies are in `.emlx` files referenced by the index.
  - **Writing is unsafe** — no documented insert protocol; bypasses sync mediator; corruption risk.
- **AppleScript** is the only official Mail.app API for creating drafts/sending.
- **IMAP** can bypass Mail.app entirely (needs server credentials).
- **No EventKit equivalent** for Mail exists.
- **Recommendation:** Use **SQLite for reads**, **AppleScript for writes** (drafts/send). Requires **Full Disk Access** for SQLite, **Automation TCC** for AppleScript.

### 4. Apple Messages
- **Direct SQLite** (`~/Library/Messages/chat.db`) is well-understood and readable.
- Similar to Mail: reads are safe, writes are not.
- **Recommendation:** Direct SQLite for read-only sync. Requires **Full Disk Access**.

### 5. Apple Photos
- **No direct SQLite access** — the Photos library is a opaque package.
- Only the **Photos TCC API** (`PHPhotoLibrary`) is available.
- **Recommendation:** TCC API only.

### 6. Apple Calendar
- Already covered by existing research (RCC-0071).
- **Recommendation:** EventKit (`EKEvent`) — same framework as Reminders. Requires **Calendar TCC**.

## Proposed SPEC Updates

| Connector | Read Path | Write Path | Permission |
|-----------|-----------|------------|------------|
| **Calendar** | EventKit | EventKit | `kTCCServiceCalendar` |
| **Reminders** | EventKit | EventKit | `kTCCServiceReminders` |
| **Mail** | SQLite (Envelope Index + .emlx) | AppleScript | FDA + Automation |
| **Messages** | SQLite (chat.db) | — (read-only) | FDA |
| **Notes** | AppleScript | AppleScript | Automation |
| **Photos** | Photos TCC API | Photos TCC API | `kTCCServicePhotos` |
