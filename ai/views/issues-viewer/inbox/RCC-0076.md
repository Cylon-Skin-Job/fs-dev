Remove the `WorkspaceSwitcher` slide-out drawer. The `WorkspaceRibbon` dropdown and Electron menu bar cover all workspace switching needs.

---

## SPEC

### 1. Remove WorkspaceSwitcher Component

**Delete:**
- `fusion-studio-client/src/components/WorkspaceSwitcher.tsx`
- `fusion-studio-client/src/components/WorkspaceSwitcher.css`
- References in `App.tsx` or other parents
- `isSwitcherOpen`, `openSwitcher`, `closeSwitcher` from `workspaceStore.ts`

**Keep:**
- `WorkspaceRibbon.tsx` — becomes the sole visual workspace switcher
- `WorkspaceRibbon.css`
- `requestSwitch`, `requestRemove`, `cycleWorkspace`, `toggleRibbon` in store

### 2. Ribbon Becomes Primary Switcher

The ribbon already shows workspace thumbnails/icons with remove buttons. It is sufficient.

**Tweak ribbon behavior:**
- Click workspace thumbnail → switch to that workspace (current behavior)
- Click × on thumbnail → close workspace from ribbon (set `ribbonVisible = false`)
- Click "Add Project" → open add modal (current behavior)
- Keyboard shortcut (`Cmd+Shift+W` or similar) → toggle ribbon open/closed

### 3. Electron Menu Bar "Workspaces"

Add to main process menu:

```js
{
  label: 'Workspaces',
  submenu: [
    // Dynamically populated from workspace registry
    { label: 'fs-dev', type: 'checkbox', checked: true },
    { label: 'my-website', type: 'checkbox', checked: true },
    { label: 'solobooks', type: 'checkbox', checked: false },
    { type: 'separator' },
    { label: 'Add Workspace...', click: () => { ... } }
  ]
}
```

- Menu stays in sync with `ribbonVisible` state
- Checking a workspace in menu = set `ribbonVisible = true`, switch to it
- Unchecking = set `ribbonVisible = false`, close it
- Menu updates when workspaces are added/removed/renamed

### 4. Workspace State Reset on Close

When a workspace is closed (unchecked or × clicked):

**Reset (discard):**
- Active view / focused panel
- Scroll positions
- Selected ticket / expanded ticket preview
- Active agent workflow
- Doc viewer centered document
- Wiki viewer selected page

**Preserve:**
- File explorer open tabs (user's working set)
- Panel widths / layout geometry (sizing always persists globally)
- Theme settings

**Implementation:**
```js
function closeWorkspace(workspaceId) {
  // 1. Mark ribbon invisible
  setWorkspaceRibbonVisible(workspaceId, false);
  
  // 2. Reset focus state for this workspace
  const state = loadState(workspaceId);
  delete state.activeViewId;
  delete state.scrollPositions;
  delete state.selectedTicketId;
  delete state.activeWorkflow;
  // ... etc
  
  // 3. Keep file explorer tabs
  // state.fileExplorer.tabs is untouched
  
  saveState(workspaceId, state);
}
```

### 5. 24-Hour Grace Period

To handle accidental unchecks:

- Workspace closed → state is soft-reset (focus cleared, file tabs kept)
- If workspace is reopened within **24 hours** → restore file tabs, sizes preserved
- If workspace stays closed > 24 hours → hard-reset on next app launch (file tabs also cleared)
- Timer stored in `~/Library/Application Support/Fusion Studio/workspace-close-times.json`

### 6. Bug Fix: Screenshot → Render Transition

**Issue:** When switching workspaces, the app shows a screenshot during transition, then switches to the live workspace render. This causes:
- **Sizing issues:** Layout jumps when screenshot dimensions don't match live render
- **Darkness issues:** Screenshot appears darker than live render (possible gamma/color space mismatch)

**Fix:**
- Ensure screenshot capture matches the live render dimensions exactly
- Apply consistent color space during capture (sRGB, not display P3)
- OR: remove screenshot transition entirely, use CSS fade between workspace canvases
- OR: show a blurred placeholder instead of screenshot, then fade in live render
