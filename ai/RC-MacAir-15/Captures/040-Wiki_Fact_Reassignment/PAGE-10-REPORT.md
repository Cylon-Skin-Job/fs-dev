> ## Choose the path
>
> Fusion Studio is an Electron workspace app. Opening an installed app, developing from source, and enabling optional features have different prerequisites.
>
> ## Use chat
>
> Current workspace chat policy is read from `ai/<machine>/System/config/cli.json`; in this development workspace, OpenCode is the enabled default and Kimi is disabled. To use chat, make the configured harness available and set up its provider credentials using that harness's supported flow. [Chat decisions](../../007-Chat_System/000-Overview_and_References/002-Decisions/PAGE.md) own the harness policy.
>
> ## Develop from source
>
> Work in the primary `fs-dev` checkout. Install the repository-compatible Node.js/npm toolchain. Install dependencies in `fusion-studio-client/` and `fusion-studio-server/`. From `fusion-studio-client/`, `npm run electron:dev` builds the renderer and opens the Electron app; its shell starts the server process. For server-only validation, run `node server.js` or `npm test` from `fusion-studio-server/`. These are development commands, not installed-app onboarding steps. The repository does not currently declare one supported minimum Node version in its package manifests.
>
> ## Development checks
>
> Browser end-to-end tests use Playwright from `fusion-studio-client/`. Installing its Chromium browser with `npx playwright install chromium` is optional for that test work. Follow the [Chat testing and operations guidance](../../007-Chat_System/005-Testing_And_Operations/PAGE.md) before running Electron tests against a live profile.
>
> ## Add a workspace
>
> Attach the project folder through Fusion Studio's workspace flow. Workspace content lives under a machine-scoped `ai/<machine>/` tree. Follow the [Workspaces and Views](../../001-Workspaces_And_Views/000-Workspaces_And_Views/PAGE.md) guidance for the current layout; the former `ai/screenshots/desktop` symlink is not a required workspace step.
>
> ## Optional features and privacy
>
> Changes to macOS screenshot location and adding credentials are user-chosen system actions. The screenshot feature reads the configured macOS source folder and, when Fusion is focused with an active workspace, copies qualifying new screenshots into that workspace's `ai/<machine>/Data/Screenshots`. See the canonical Screenshot Capture and Secrets Manager articles for their current setup and limits. GitLab and background automation have separate setup and capability guidance. A configured AI harness or external integration may communicate with external services; do not assume all task data stays on this Mac.
>
> ## Alpha dogfood installation
>
> Alpha is a separate source checkout and installed app. Development checkout changes do not update it. Follow the machine's approved Alpha workflow for a requested sync, rebuild/install, or restart, preserving both its user-data profile and `RC-Alpha` machine identity. Alpha deployment is not part of normal source setup.

The Workspaces heading path in the proposed link exists. Alpha-specific shell commands, install replacement, and verification belong a future Operations Packaging article or the existing root `AGENTS.md`; do not duplicate machine-specific absolute paths in a generic setup article. Onboarding prose should link verified GitLab/Secrets/Agents/Screenshots successors only once those articles exist. `006-Operations/PAGE.md` should route to the new Setup article and remove its old migration-source link after the successor is live, with a preserved preimage.
