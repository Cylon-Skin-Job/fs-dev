> ## Current legacy run record
> The ticket dispatcher can start the legacy agent runner for an eligible assigned ticket. The runner creates a timestamped folder under the workspace's resolved Agents operational root. It writes `manifest.json` with run, agent, ticket, prompt and lifecycle fields, and an initially empty `run-index.json`. When their source files exist, it copies the ticket, selected `PROMPT_NN.md` and `LESSONS.md` into the folder. The runner updates the manifest when the wire process starts or exits and appends a one-line entry to the agent's `HISTORY.md` on exit. These are operational records, not governed automation facts or proof that every wiki edit has a corresponding run.
>
> ## Evidence gaps
> The runner does not produce a fixed gather/propose/execute/verify step set, an edge-propagation graph, or run-local before/after `PAGE.md` snapshots. It reads server `AGENTS.md` and the selected live prompt to build context, but does not freeze the complete effective instruction context. Existing mediated-save preimages and eligible agent observations are separately owned evidence; an observation is not necessarily a pre-edit image. Consult the [Automation Run Provenance Schema](../../010-Events_And_Ledger/003-Provenance_Model/006-Automation_Run_Provenance_Schema/PAGE.md), [File Version Provenance Schema](../../010-Events_And_Ledger/003-Provenance_Model/005-File_Version_Provenance_Schema/PAGE.md) and [Audit Query And Review Provenance Schema](../../010-Events_And_Ledger/003-Provenance_Model/008-Audit_Query_And_Review_Provenance_Schema/PAGE.md) before drawing a cross-source conclusion.

> ## Review questions

Cite the record or file history for each answer. A later edit or nearby event is a signal to investigate, not proof of false convergence or causation.
