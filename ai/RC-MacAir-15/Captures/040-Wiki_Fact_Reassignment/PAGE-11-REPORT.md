## 4. Proposed integrated destination prose

### T — proposed `003-Automation_And_Agents/002-Ticketing/PAGE.md`

Proposed page title: **Ticketing: Board Data and Authoring**. The coordinator should merge P13's unique writing criteria here, rather than creating a second canonical ticket-authoring page.

#### Board data and columns

“The Issues board loads `ai/<machine>/Issues/content/tickets.json`. Its `tickets` object is keyed by ticket ID. Each entry needs the core display fields `title`, `assignee`, `created`, `author`, `state`, and `body`; some current entries also include `priority`, and the ticket type allows `gitlab_iid`. The JSON body supplies the card preview and both built-in detail views. The Markdown file is a companion record; the board does not load its text. A Markdown-only ticket will not appear. The board places `state: closed` entries in Completed. For `state: open`, it places entries assigned to one of the UI's fixed `kimi-wiki`, `kimi-code`, `kimi-review`, or `kimi-bot` names in Open, and other assignees in Inbox. These names are a display test, not a dispatch or registry lookup. The containing Markdown folder does not choose the column, although file actions derive a path from that column logic.”

#### Creating a visible ticket

“For current manual authoring, choose an unused `RCC-NNNN` ID after checking both JSON keys and Markdown filenames. Write `Issues/inbox/<id>.md` with identifying frontmatter and substantive body, then add the matching ID to `Issues/content/tickets.json` with the core display fields and a useful `body`. Set `state: open` and a human assignee for a normal Inbox ticket. Use an ISO 8601 creation timestamp and update `last_updated` when editing the JSON for traceability. The JSON entry creates visibility; the Markdown file keeps the durable companion and other file-based readers in sync. The present workflow has no safe concurrent ID allocator, so resolve collisions before saving.”

#### Write a useful ticket

“State the observed confusion or bug, why it happened, the likely owning files or architecture gap, the user impact or risk, and concrete acceptance criteria.” This unique P13 material belongs here, with a link from V rather than a duplicate article.

#### Updating a ticket

“Change the JSON `state` to `closed` to move a card into Completed. Update the matching Markdown frontmatter as well so other readers have the same state. `last_updated` is a maintenance field, not a condition checked by the current board renderer.”
