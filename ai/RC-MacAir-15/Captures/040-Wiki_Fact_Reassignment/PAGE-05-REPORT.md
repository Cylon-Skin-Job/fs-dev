> ## Startup ownership
> Server startup initializes `fusion.db` and the event/subscriber authority before opening public sockets. It registers request handlers and broadcasters, starts thread/audit lifecycle services, validates registered workspaces, and starts harness-status revalidation without blocking `listen()`. Registered but unavailable workspace rows remain in the registry for UI reporting. Theme CSS regeneration and workspace CLI-config ensure are guarded effects. Request-handler registration alone does not read Keychain; the caller's request or an enabled adapter determines that effect.
>
> ## Configuration and calendar adapters
> The server's implemented background-service opt-ins are `settings.backgroundServices.calendar.apple.enabled` and `.google.enabled` in `fusion-studio-server/data/config.json`, with `FUSION_CALENDAR_APPLE_ENABLED` and `FUSION_CALENDAR_GOOGLE_ENABLED` overrides. Both default off if the value is absent or the config is unreadable. Enabling Apple starts its watcher only when the local Calendar SQLite file exists. Enabling Google starts an immediate sync and five-minute poll; only that enabled path asks for `GOOGLE_BRIDGE_URL` and `GOOGLE_BRIDGE_KEY` and posts to the bridge. Calendar HTTP routes are request-driven reads from local `calendar_*` tables. The current client store's create/update/delete functions do not write back.
>
> ## Workspace pipeline
> After `listen()`, the active workspace's file watcher, declarative filters, optional component definitions, trigger definitions, cron jobs and runner heartbeat start through the view-readiness gate. No active workspace or unavailable view registry skips that pipeline. Configured cron triggers may create tickets; file and event triggers may run configured actions, including a webhook POST. These trigger paths currently use the legacy event bus and have no general automation opt-in in the inspected startup path. The runner heartbeat timer starts even if no run is active.
>
> ## Client-initiated background work
> Renderer boot checks `fusion.clipboard.monitor.enabled` in localStorage. Only the value `true` starts one-second system clipboard polling; changed nonempty text is sent as `clipboard:append`. Electron workspace activation still schedules a native panel screenshot capture without an opt-in, and workspace initialization requests the screenshot list. Browser bookmark favicons currently resolve through Google's favicon service. Shared styles, panel discovery and Calendar data loads are client requests; consult their view owners for details.
>
> ## Failure boundaries and known gaps
> Watcher subscribers, legacy event-bus listeners, cron ticks/retries and runner heartbeat callbacks run through `background-services/safety.js`, which catches synchronous throws and observed promise rejections. Failures reaching that boundary append a redacted generic JSON line to `fusion-studio-server/data/background-services.log` and print a generic console error; the file does not contain the original service name or error code. The cron scheduler and hold registry expose `stop()`, but the inspected server shutdown composition does not call those stops. Do not infer that all startup or external failures use this log: database initialization is startup-fatal and other paths have local catches. New cross-capability work follows the governed event/provenance standards; legacy `emit/on` is not governed admission.

Keep links to Chat Runtime, Background Agents, Screenshot Capture, Clipboard, Calendar and Universal Event Bus owners, rather than repeating their full contracts here. The exact calendar config path is what the inspected module reads; its packaged-app profile semantics need separate verification before promising user-specific persistence.
