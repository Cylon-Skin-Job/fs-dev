## 4. Proposed destination prose and source metadata

### Chat Runtime / “Warm And Cold Runtime” (merge with existing section)

> “Warm” refers to an activated provider runtime for one chat session, addressed by `threadId`. Passive `thread:open` reads SQLite exchange history and an optional in-memory live-turn snapshot without spawning or warming the provider. Explicit Warm, composer intent, a prompt or automation can activate it. `SessionManager` holds the live provider sessions, with current `ThreadManager` defaults of 10 active provider sessions and a 9-minute provider-session idle timer. Capacity is enforced against live provider sessions; it is not a limit on visible or persisted conversations. A separate 45-minute `thread-lifecycle-controller` timer emits `thread:idle_expired` after a turn becomes idle; that observer does not itself evict threads or provider wires. The exact runtime/Stop owners retire providers, while transcript and metadata remain in SQLite for later hydration.”

This is a **proposed merge**, not a second replacement for the existing passive-open, Stop, group identity, or persistence sections. Source files to add/check for this paragraph: `fusion-studio-server/lib/thread/session-manager.js`, `fusion-studio-server/lib/thread/session-lifecycle.js`, `fusion-studio-server/lib/thread/ThreadManager.js`, `fusion-studio-server/lib/thread/thread-lifecycle-controller.js`, `fusion-studio-server/lib/startup.js`, and `fusion-studio-server/lib/thread/thread-open-handler.js`.
