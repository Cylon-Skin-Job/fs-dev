> ## In-app captures and chat attachments
>
> In the desktop app, **Take screenshot** captures the focused Fusion Studio window. The server saves the PNG under the active workspace's `ai/<machine>/Data/Screenshots/`, and the current chat receives a pending file attachment. The Screenshots gallery lists image files from that same workspace folder and can attach an existing one. These file screenshots are distinct from workspace preview images: previews capture the app panel area on workspace changes and are stored as one PNG row per workspace in SQLite for the ribbon and carousel.
>
> ## macOS screenshots
>
> Fusion Studio reads the macOS screenshot location from `com.apple.screencapture location`; its fallback is `~/Desktop`. While the app is focused and a workspace is active, the server watches that folder and copies newly added `Screenshot …` PNG/JPEG files into the active workspace's `ai/<machine>/Data/Screenshots/`. The file gallery reads the workspace copy. The app does not need an `ai/screenshots/desktop` symlink for this flow.
>
> ## Optional macOS location change and direct CLI access
>
> Changing the macOS screenshot destination to `~/Desktop/Screenshots` is optional. Create the folder first, record any existing `com.apple.screencapture location`, then change the setting and apply it through macOS. If the app is already running, refresh its screenshot source or restart it so the watcher follows the changed folder. To undo the change, restore the previous custom location if one existed; otherwise remove the override to return to the default. This is a user-level system change, not a Fusion Studio requirement.
>
> If a CLI working in this repository needs a stable filesystem route to the macOS source folder, a user may separately create `ai/screenshots/desktop` as a symlink after creating its parent directory. This merely exposes the target path to processes with appropriate permissions. It does not make the target read-only, route captures to a workspace, or feed Fusion Studio's gallery. Check for an existing path before creating or replacing a link.
>
> ## Storage and privacy
>
> In this checkout, `ai/.gitignore` excludes `ai/screenshots/`, and the root `.gitignore` excludes the machine-scoped `ai/RC-MacAir-15/Data/` tree. Ignore rules affect ordinary Git tracking only. Saved screenshots and previews can contain sensitive content; review files before attaching them to an AI chat or sharing the workspace. The gallery limits its display to 20 items but does not implement a 20-file retention policy. Removing a saved image can break a chat attachment that points to it.

The destination should link to the canonical current Chat UI/attachment documentation for how pending attachments reach a harness. It should link to Operations Setup only for optional system setup; do not copy the old Kimi onboarding page. If the coordinator finds a current dedicated screenshot article created concurrently, merge there instead of creating another home.
