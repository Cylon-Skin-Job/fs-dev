## Orchestrator interpretations recorded at dispatch (binding for builders unless superseded by a validated finding)

1. **Production composition preservation.** SPEC-02 §3/§5.3 keeps one workspace Legacy host (`viewId:null`, `host:'legacy-main'`) as the visible production chat composition; view-bound `ThreadedChat` composition is introduced and proven through explicit hosts (real components + explicit identity/store bindings, including rendered fixtures for two registered views) without placing view-bound rails into production view chrome. This preserves current user-visible behavior while making no Side Chat or Generic Host placement change. A builder that finds accepted current bytes requiring a different production mount must record the deviation and return it to the orchestrator before exceeding the SPEC's stated scope.
2. **Legacy population request ownership.** The legacy rail/list request follows the active connected host; inactive mounted panels must not issue duplicate unqualified `thread:list` requests or steal selection. The `{workspaceId, viewId}` composite key remains the population key even when `viewId` is null (collision-safe composite key allowed, SPEC §6.1).
3. **Transient `surfaceId`.** Non-component hosts mint `surfaceId` at mount from their own runtime mount generation and never invent a component instance; component-backed mounts derive it from `componentInstanceId` + runtime mount generation (BRIDGE-02 overlay §2 rule 4). It is never persisted, never in descriptors/envelopes/results/fan-out/records, and never session authority.
4. **Prompt `harnessConfig`.** Send snapshots the last server-acknowledged `{model, variant}` for the exact `threadId`; it never reads `composerModelConfig[currentPanel]` or whichever panel became current after the user acted. Pending optimistic selection never becomes Send authority.
5. **Test isolation.** New Playwright specs run only under a CHAT-02 isolated config (fresh port and `/tmp` profile, isolated DB); never port 3001, the dev DB `fusion-studio-server/data/fusion.db`, or the Alpha profile.
