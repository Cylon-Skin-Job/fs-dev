## D15 — bounded timeout recovery correction (supersedes D08's first timeout policy)

Source inspection established this earlier implementation defect: the first implementation returned on the3s effect timeout before stopHarness; normal OpenCode turn completion emits no inert-proxy exit and the idle timer was removed, so persistence could settle while compute/session stayed STOPPING. The former D08 statement that timeout simply retains STOPPING was an insufficient policy, not accepted final behavior. Earlier source and raw failed/passing artifacts are preserved.

Current repair keeps the3s exact save-effect grace but, after timeout, still terminates the captured provider, suspends metadata and releases only the exact session/runtime after proven termination. `wire/terminal-saved-delivery.js` is a focused transport-only owner: a one-shot real saved-event listener captures immutable workspace/root/epoch/thread/turn, current connection, canonical ownership and expected provider session. It shares payload projection and an event-local successful-send WeakSet with the normal synchronous broadcaster, preventing duplicate delivery and allowing fallback if the normal send fails. It invents no saved ACK, owns no canonical runtime map or durable state, and is canceled on matching event, failed/settled effects, Stop failure, connection close or30s deadline. Existing `drainEventEffects` accepts AbortSignal so cancellation releases its timer/listener as well. Ownership is rechecked after provider awaits; replacement cannot be stopped, cooled or receive old fallback ACK.

Touched production owners: runtime-stop, runtime-session-binding, event-bus, wire-broadcaster and new terminal-saved-delivery; focused owner inventory includes all. New stop-timeout-recovery tests use actual SessionManager/SessionLifecycle, actual OpenCode inert process proxy and real stop method with a controlled OS child boundary and controlled durable effect. They assert delayed success/failed effect, provider termination+session/COLD cleanup without proxy exit, no forged ACK, permanent effect30s listener/timer bound, different turn, runtime/connection/provider replacement, provider failure without premature cooling, normal/fallback send race and connection-close cleanup. Existing timeout test now expects provider cleanup instead of pinned compute. No provider-specific implementation was changed.

Explicit limitation: genuine persistence after the30s transport deadline requires existing history/reconnect recovery; delivery beyond that deadline is not guaranteed. Underlying storage failure remains truthful and cannot fabricate saved status. Provider termination failure continues fail-closed rather than releasing an unproven live provider. Proposed classification: **accepted**, necessary05A/05C-integrated repair; authoritative disposition remains orchestrator-owned. Rerun invalidated full server/backend/submission/actions/architecture checks; build reused because no client product changed.

Fixture adaptation is only an exact source-match update to inject the pre-existing `before-save-ack` and `after-save-ack` gate around `deliverSavedExchange` instead of the former inline send. Drop remains a drop. Backend#8 failed staging before app launch on the old needle and preserved clean cleanup receipts.
