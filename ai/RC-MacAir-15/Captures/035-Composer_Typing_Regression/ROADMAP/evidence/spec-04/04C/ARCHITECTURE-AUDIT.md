# 04C Architecture Audit

The production renderer now has one explicit per-view shell composition in `WorkspacePanel`. `ViewChatShell` terminates view/session subscriptions and passes projections to the rail and chat. `ContentArea` is a sibling and selects only the exact panel configuration row. Draft and live updates therefore do not flow through the content owner. The final 60-test observation lane proves draft-local history/header/rail/content quietness and inactive-host command discipline.

`LegacyChatHost.tsx`, `useLegacyChatHost.ts`, `ViewWorksurfaceDock.tsx`, and its CSS are deleted. Production source has zero matches for those names, `legacy-main`, or `data-worksurface-dock`. The only production host placement is the shell composition; built-in content surfaces no longer mount hidden duplicate chat docks. Component descriptors require a non-null durable `viewId`; persisted null-view history remains supported by the existing store/server read and cleanup routes and tests, without a renderable null-view compatibility host.

The explicit session projection (`useChatSessionHost`) and command owner (`useChatSessionActions`) do not subscribe to draft, transcript, live-segment, prompt-listener, or action-bridge state as an aggregate. View population observes only its exact rows and the member arrays keyed by those rows. Active hosts issue one qualified list per connection/address; inactive hosts issue none. Workspace bootstrap no longer requests or opens the retired null-view population, and the former five-view reconnect Side Chat sweep is removed. Persisted adapterless Side Chats materialize when their exact view becomes active. The real shell gate records exactly one startup list for the active view, zero null-view lists, and zero startup opens. Passive opens remain passive and never warm; assistant creation remains `thread:open-assistant`.

No changed production host module creates an unbounded `Map` or `Set`. The accepted 04B revision/cache lifetime is untouched. The source architecture gate reports no aggregate owner and enforces all new core files at <=400 physical lines. Core counts are: App 332, WorkspacePanel 129, ContentArea 128, ChatArea 80, ChatSessionHost 99, useChatSessionHost 193, useChatSessionActions 309, useViewChatHost 265, ViewChatHost 61, component mount 132, contracts 171/118. The additionally touched extracted `worksurfaceFrames.ts` remains 366 lines and `worksurfaceController.ts` remains an 84-line facade. The pre-existing workspace/thread protocol dispatchers remain cohesive routing exemptions at 824/625 lines; 04C only deletes hidden Legacy command ownership and adds no responsibility.

Three inherited content implementations exceed 400 lines: CaptureTiles 563, OfficeGrid 1018, and EmailGrid 1463. 04C's touch in each is strictly subtractive (removing the retired duplicate dock import/mount and now-unused selectors). Each remains the pre-existing cohesive view implementation; splitting them would be an unrelated high-risk refactor. This is the exact requested cohesive exemption. FileExplorer 76 and WikiExplorer 199 need no exemption. `LiveSegmentRenderer` was not changed or mechanically split.

The final sustained R1 oracle is 383 lines and owns one bounded measurement job. Bootstrap traffic evidence is capped at 2,048 decoded type/direction/timestamp records and fails closed on overflow; measured outbound evidence is separately capped at 64 records and zero frames remain required. The event-driven pre-measurement boundary observes the complete screenshot capture/update/request/data lifecycle plus sequence stability, so it neither filters product traffic nor introduces an arbitrary sleep. Its wall limit is derived directly from the approved `characters × delay × 1.5` rule.

Source checks also preserve 04A composer/header/history boundaries, 04B mounted-row cache lifetime, and the exact attempt/submission/action/correlation contracts. No migration, database, server route, live profile, Alpha, or SPEC-05 behavior changed.
