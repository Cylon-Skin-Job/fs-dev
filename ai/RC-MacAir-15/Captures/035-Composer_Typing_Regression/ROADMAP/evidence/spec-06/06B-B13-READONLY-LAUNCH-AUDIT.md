## Lifecycle ordering and evidence gap

Playwright's preload saves native app.whenReady, intercepts the ready emission and exposes its own isReady/whenReady promise. Once Node/browser transport initialization completes, __playwright_run releases that readiness promise/event. It does not hold all native activation events. Fusion registers its scheme, name and isolated userData path before readiness; its single-instance lock gates the entire window startup. After readiness it awaits server readiness and workspace binding, installs handlers, creates the hidden BrowserWindow, loads the shell and shows on ready-to-show. Its app.activate handler is registered after window creation. No recorded evidence establishes that a missed activate event caused B13; the later explicit show/app.focus/window.focus sequence also failed to establish focus.

stageAndLaunch returns only after launch, firstWindow, shell URL and renderer Connected checks. None checks native foreground. In this fixture the sequence occurs **twice**: first launch creates project/chat, closes the owned app and waits300ms while checking its captured child tree; F2/F3 data is materialized; the same staged entry/profile is launched again. Only after the second Connected check are B13's native trace and protocol tap installed. B13's 02:35:56.764 main-observer installation is already inactive/unfocused. The old focus-state module writes only a changing snapshot under the disposable profile and that snapshot was not preserved as early event history. The current source therefore exposes an actual pre-observer coverage gap, but supplies no recovered event within it. Do not infer initial grant, resignation, policy transition or first-app residual interference.
