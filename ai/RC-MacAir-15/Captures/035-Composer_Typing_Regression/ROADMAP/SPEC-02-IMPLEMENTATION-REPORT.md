## Implemented contract and source ownership

The client transport returns a typed enqueue result. A definitive no-enqueue leaves the draft editable with not-sent feedback; an ambiguous send becomes an unresolved session attempt. The session-owned submission store keys immutable attempts by workspace and thread, with request ID, submitted draft revision and attachment generations. Normal and recovered ACK paths require exact workspace/thread/request identity and a server turn ID. The user bubble uses the server turn ID; cleanup touches only the submitted revision and matching attachment generations, preserving later edits and stable-ID reattachments. Two mounts of one session share one attempt, while another session stays independent. Server persistence and ACK use the explicit target thread, not mutable selection.

Migration 045_prompt_submission_receipts.js follows previous head 044_thread_group_placement_outbox.js. The receipt journal belongs to an authorized thread and cascades on thread deletion. The admission service reserves before activation awaits, compares canonical fingerprints and serializes same-key admission and status. Status for an absent request writes a cancelled recovery fence, preventing a delayed original from later admitting. Receipt acceptance and group activity commit in one transaction, then the runtime emits the receipt-owned ACK and durably claims dispatch before invoking the adapter. An exact duplicate returns the original accepted turn without another Fusion dispatch; a mismatched fingerprint is rejected. Startup cancels old reservations and marks accepted but unclaimed receipts interrupted_before_dispatch. Known post-commit failures persist failed_before_dispatch; claimed rows remain accepted with unknown_after_dispatch_claim. Existing exchanges, null-view rows, provider syntax and canonical transcript ownership remain on their established paths; no old request IDs were fabricated.

The authenticated recovery wire is thread:action with action prompt_receipt_status, threadId and requestId. The server derives workspace ownership from the authenticated binding and returns exact receipt outcome, execution, turn ID and accepted content when applicable. The client uses accepted content only to reconstruct its normal server-owned message:sent ACK. It never resends the prompt or calls a provider during status recovery. Connection generation, authenticated workspace binding and request ID scope replies; a lost reply times out after five seconds. Connected retries use bounded 1/2/4/8/15-second delays. The 15-second admission deadline releases editing and shows unknown without enabling resend. Acknowledged attempts remain watched until exact turn begin, live snapshot or saved exchange; disconnect/restart can query their execution status. Definitive rejection/cancellation allows a new deliberate Send. A pre-begin accepted failure clears only matching Stop/orb and shows feedback without an invented assistant row. A post-begin failure retains partial output and the established terminal/save reveal sequence. Hydration preserves server-issued accepted user rows until saved exchanges with matching turn IDs replace them.
