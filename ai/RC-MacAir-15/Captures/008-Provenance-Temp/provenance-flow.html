Provenance Flow Sketch

Draft diagram for how UI actions, harness events, resource mutations, render sync, and ledger/versioning should share one provenance model without treating provider-specific OpenCode IDs as canonical.

Canonical Event Flow

Renderer UI Action Module

When Wiki Viewer or File Viewer is active and at least one provenance-valid pending resource attachment exists, captures best-effort non-ID context and optional clientCommandId only when chat.send_with_resource is actually sent. Attachments may originate in any panel. Provenance-invalid entries are diagnosed/omitted only from canonical subjects; the separately validated operational prompt attachment list and order never change. Navigation, selection, and attachment staging emit nothing.

command envelope

First Accepting Server Handler

Accepts and starts the source command independently, then uses only the fixed-schema nonrecursive bounded extractor to copy recognized own-data seed fields. Deep/wide/over-cap input is ignored without retaining the original object or affecting the prompt. The admission executor later generates uiActionId and canonical fields.

ui.action candidate

UI Validation + UEB Admission

Blocked on UEB-D01: a nullable private owner cell makes command completion/cancel/throw win atomically over late provenance installation. After the operational command path starts, extraction separates the transient workspace token from an already-frozen token-free queued envelope; binding/target preflight drops the wrapper/token before slot allocation and performs no second envelope copy. Nullable slot failure or install-after-close offers nothing. The fixed offer receives a successfully installed slot only synchronously; the supervised admission task's data plane owns only the token-free envelope, targets, and bound context, while its queued control plane owns one private, accounted AcceptedRefSlotTaskLink with atomic setup/admission-or-finalization and exactly-one settlement. D01 must first approve exact bounded capacity, concurrency/fairness, overload, retention, cancellation, shutdown/restart, and diagnostics for admission and listener delivery. UEB then accepts only a privately prepared candidate, clones/freezes the event, binds its identity to an opaque ref, freezes one { acceptedRef } context, and offers exact listener(frozenEvent, deliveryContext) tasks under that contract. The command never awaits, retries, or receives backpressure from this work.

independent eventual provenance; operation already running

Successful Command / Mutation

The operational command starts before provenance submission and runs independently of its outcome. A resource.* candidate exists only after the owning mutation succeeds; failed mutations produce no resource fact or invalidation. A downstream producer binds only an already-available ref. Missing, stale, forged, mismatched, or wrong-workspace proof atomically omits its relationship group with fixed code-only diagnostics while the independently safe fact continues.

accepted UI reference when available; command continues

Watcher / External Change

Chokidar observes filesystem facts. If no direct initiator is known, provenance remains external, unknown, correlated, or inferred.

Harness / Tool Event (Later, Blocked)

Future contract: preparatory harness identity is not canonical publication authority. Harness/started activation is blocked on TOOL-D02; tool args/results also require TOOL-D01 and SPEC-40b2b registration.

Independent operational trigger fork:
An established workspace-watcher observation reaches the one operational file-trigger matcher exactly once without awaiting canonical construction or admission; mutation handlers do not invoke a second matcher. The minimal resource observation is scheduled independently before optional watcher stats/tokenization. Rejected or failed provenance can omit correlation, but cannot suppress or duplicate trigger execution.
normalize bounded fact core; copy already-available metadata only

Resource Event Producer

Server file APIs and watchers construct bounded resource.* candidates. Automation-origin canonical identity is later and blocked on AUT-D03, the applicable SPEC-40b2c registration, and accepted-only propagation; operational automation continues without it. No enrichment lookup, I/O, directory scan, or tokenization precedes admission or renderer invalidation.

candidate canonical event

Resource Validation + UEB Admission

The publisher validates the post-fact resource candidate. UEB clones/freezes/binds it, freezes one deliveryContext, and, after UEB-D01 closes, offers exact listener(frozenEvent, deliveryContext) tasks to the bounded executor. Each admitted delivery uses that ABI; saturation skips/finalizes only the affected delivery. Rejection/suppression returns no ref and invokes freshness recovery.

Post-mutation / watcher-observation failure branch:
Pre-admission validation/publication failure exposes no ref or canonical delivery. Post-admission render-projection failure preserves the accepted ref and delivery for other subscribers; only that projection fails. Both preserve the mutation/observed fact, diagnose, and send non-canonical resource:refresh_required. Clean entries refetch; dirty/optimistic state uses the conflict shadow.
published canonical event + accepted reference

Resource UEB Subscriber Fanout

This is bounded queued fanout under UEB-D01, not a second admission. Every admitted subscriber delivery receives the same frozen event and frozen delivery-context object; a saturated delivery is independently skipped/finalized. eventId is identity and dotted eventType is classification.

fan out to subscribers

Ledger (Later, Blocked)

No first-package ledger write: after LED-D01 settles hashing and LED-D04 settles idempotency, transactions, and bounded retry/terminal behavior, SPEC-35b may store an ordinary validated safe payload with its approved hash, the exact admitted registered UI failure-safe-core with null hash, or a restricted defensive fallback with fixed ledger_defensive_fallback. SPEC-40c later permits historical capability only for the hashed ordinary branch; every null-hash row is ineligible. Resource redaction failure branches before UEB; row keys remain storage-only.

Resource Sync

Derives cache invalidation and renderer updates. It is not the canonical event.

Validated Resource Event

The same UEB event carries ids, actor, provenance, context, resources[], and resourceMutation.

Versioning Subscriber (Later, Blocked)

Consumes accepted resource events only after its storage gates. Individual metadata/hash-only rows require ULV-D03, ULV-D05, ULV-D10, the non-batch event-contract decision ULV-D12, accepted SPEC-35b, and active 40b2d1. Snapshots, diffs, and blobs additionally require ULV-D02 and active 40b2d2. Storm batches require ULV-D03, ULV-D04, ULV-D05, ULV-D10, accepted SPEC-35b, and active 40b2d3; storm snapshot/diff references additionally require ULV-D02/40b2d2. Edges require accepted SPEC-35d; compaction/drop requires accepted SPEC-35f. Any caused_by edge additionally requires the exact owner-approved LED-D03 matrix.

UI-Origin Path

The first adapter pair is Wiki Viewer and File Viewer. The first durable action requires one of those panels to be active plus at least one valid pending attachment from any panel when chat.send_with_resource is actually sent; unsupported panels or no-valid-attachment sends stay on the legacy path. Navigation, selection, and staging do not emit. Renderer capture is pure and capped at 32 subjects, 512 steps, and 16,384 seed bytes; overflow sends the unchanged baseline. Workspace token entropy is detached and notifications never await it; token allocation/transport remains blocked on RSC-D17's exact bounded executor, binding-retention, cancellation, saturation, and shutdown contract. After operational validation starts the command, the server schedules provenance outside the command/response chain. Optional enrichment is omitted unless already available, and downstream relationships bind only an already-available accepted ref. First-package legacy chat:* facts receive no UI ID until CHAT-D01 closes and SPEC-40b2a registers their exact canonical contract.

Harness Path

Harness attribution stays provider-neutral through harnessId, harnessRunId, and harnessEventId. OpenCode IDs are kept as native references.

Render Path

React/Zustand normally refreshes from resource-sync projections. Pre-admission failure has no canonical event/ref. Projection failure occurs after admission, keeps the frozen canonical event/ref valid for other subscribers, and uses resource:refresh_required for renderer freshness.
