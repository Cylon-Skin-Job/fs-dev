## What This App Is

Fusion Studio is a **web-based IDE that wraps command-line AI assistants** in a rich visual interface. It supports multiple CLI harnesses:

- Kimi
- Claude Code
- Codex
- Gemini
- Qwen
- OpenCode

The AI inference runs in CLI processes on the backend; the browser renders streaming output with animations, tool displays, file explorers, and workspace management.

## Key Subsystems

### 1. CLI Harness System

Each supported CLI has a harness that:
- Detects installation (`which` / `--version`)
- Spawns the process with thread-specific arguments
- Parses JSON-RPC wire protocol from stdout
- Translates CLI-specific events into canonical events

Modes: `legacy` (direct spawn), `new` (structured harness), `parallel` (A/B validation)

### 2. Pulse-Driven Render Engine

Streaming AI output is decoupled from visual presentation:
- Tokens arrive via WebSocket and buffer in Zustand
- `LiveSegmentRenderer` gates display through an **Orb animation** (~2s) that buys buffer time
- Segments reveal **sequentially, one at a time**
- Typing speed is **adaptive**:
  - Fast (1ms/char, batch 5) when content is buffered ahead
  - Slow (6ms/char, batch 1) when waiting for next token
- Tool calls have dedicated animated displays with shimmer → reveal → collapse lifecycle

### 3. Thread Management (Dual-Scope)

- **Project scope:** Threads shared across all views in a workspace
- **View scope:** Threads tied to a single panel, reset on panel switch
- Persist to both **SQLite** (`exchanges` table) and **Markdown** (`CHAT.md` with frontmatter)
- Session idle timeout: 9 minutes (then suspended, resumable later)

### 4. Background Agent Runner

Autonomous ticket-based work that:
- Spawns its own CLI sessions
- Monitors heartbeats and nudges stalled runs
- Updates manifest + history on completion
- Optionally pushes results to GitLab

### Assessment
The project is **functionally mature** (complex streaming renderer, multi-harness support, full thread persistence, calendar/bookmarks/secrets, background agents) but **documentation is stale**. The `fusion-studio` branding is current, the `ai/<machine>/Views/` registry is the real workspace system, and the render engine exists in practice even though the original architectural spec says otherwise.

## Notable Design Patterns

1. **Pure Renderer Components:** No `setTimeout`/`setInterval` in components; all timing lives in the engine
2. **One Bridge, One Direction:** Engine → Bridge → Store → Components
3. **Buffering Is the Goal:** Ribbon, pauses, and typing effects deliberately stall the UI so content is always ahead of display
4. **Project-Scoped Intelligence:** Every project gets its own `ai/` folder; the IDE's intelligence travels with the repo
5. **Secrets in macOS Keychain:** No `.env` files; credentials stored via Keychain (account: `kimi-ide`)
