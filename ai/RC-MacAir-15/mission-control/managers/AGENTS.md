# Mission Control manager homes

> Entry contract for the five owner-requested manager folders. Folder creation does not install a Codex profile or activate a manager session.

## Scope and entry

Read the selected manager's local AGENTS.md and handoff.md. Read [recordkeeping.md](recordkeeping.md) for records that the assignment will create or consume. The parent [Mission Control instructions](../AGENTS.md) and repository guidance remain applicable; explicit owner requests and side-conversation restrictions take precedence. Do not infer permission to dispatch agents, start monitoring, change Git state or take over a session merely from this folder layout.

The owner requested five distinct roles and a folder for each. Local manager guidance preserves that split. A manager's memory folder, runtime session, profile installation and any product checkout are separate identities. These homes are construction outputs; D-004's operational-startup constraint has not been changed.

## Record ownership

Managers keep their own current handoff and assigned operation records. Detailed work progress belongs to the workfolder or existing SPEC/ticket ledger that owns it. Link to those sources instead of copying them into five manager histories.

The intended role split is WorkFolder Manager maintaining catalog/bindings, Status Manager observing registered work, Staging Manager recording sequencing assessments, Git Manager recording Git/integration outcomes, and Discussion Manager recording discussion synthesis and handoff packages.

Existing ../registry.md, ../decisions.md, ../handoff.md, root index/config and live workfolders retain their current writers and authority until a coordinated cutover. This new package is not a competing registry. Submit proposed shared-file changes to their designated integrator. An owner-requested ticket edit remains governed by D-020; coordination is not a second approval gate.

## Authority and evidence

Preserve source intent, revisions, unchanged native work IDs and evidence. Label proposals, observations, owner decisions, implementation results and acceptance distinctly. Raise consequential missing intent; do not invent a product decision. Check the relevant current source rather than treating a dated handoff as fresh proof.

Use verified task IDs/hosts only. Side conversations identify themselves as Codex side chat (ephemeral), with a UTC timestamp. No manager folder creates a checkpoint identity or authorizes rebinding history. A recorded request or bulletin entry is not proof that another session received it.

## Maintenance

The static index routes documents; it contains no live assignment state. Re-read files before writing, preserve other sessions' changes and update the relevant local index when document paths/roles or H2 sections change. Use ../.agents/skills/mc-memory-maintenance/SKILL.md and its validators for record/schema operations. Do not create empty operation folders, review reports or logs in advance.
