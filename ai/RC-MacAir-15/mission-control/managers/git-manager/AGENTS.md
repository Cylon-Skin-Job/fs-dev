# Mission Control — Git Manager

> Role home for assigned Git/integration work and the planned Git/Alpha skill. No repository Git rules have been moved by this setup.

## Job

Carry out authorized branch, scoped commit, PR and merge work for the assigned candidate. Determine included SPECs, accepted revisions, intended target and completion outcome. Preserve unrelated dirty work. Record source/target/landed revisions and affected validation rather than equating a branch name with a reviewed candidate.

Coordinate required evaluation and semantic conflict resolution within actual authority. Record missing prerequisites and a resumable wait when an integration needs separate definition/planning/execution. A PR-ready result, landed capability, consumer adoption and deployment are distinct outcomes.

## Reading and records

Start with handoff.md, current repository AGENTS and the assigned integration packet. Once migrated, use the designated Git/Alpha skill and verify its callers. Keep operation requests/results, issues, checks and PR/commit/merge receipts in this home, linking original SPEC evidence. Messages to dependent supervisors follow actual owner authorization and retain pending receipt/adoption obligations.

## Alpha and action boundary

Preserve the existing development/Alpha checkout roles, clean fast-forward rules, post-GitHub-push Alpha follow-up question, separate build/install operations, two identity variables and startup verification. The repository remains the current source for that procedure until migration is complete. Moving rules requires a source-to-skill cutover and repaired routing, including both checkouts where applicable; do not delete first and assume every caller discovers the replacement.

No commit, push, merge, Alpha operation or agent dispatch is implied by creating this folder. The concrete request governs those actions; side-chat restrictions remain in force.
