# Next Few Weeks — Working Concept and Project Checklist

> Living project checklist, started October 5, 2026. Add, remove, split or reorder items as the concept develops with the owner. Detailed scope, dates and implementation plans are settled project by project.

## How we will use this

The agreed opening sequence is Chat System Repairs (#1) → Chat Harness Repair and Testing (#3) → Chat Session Management (#2). Project numbers are stable references as the working order changes. After them, work can follow parallel lanes and rejoin where a consumer needs shared contracts. Build reusable foundations before the features that depend on them. The HTML timeline shows the working joins and lists prerequisites in each project's description; exact release conditions remain project-shaping work. Prepare or reuse each project folder when we reach its discussion, rather than provisioning all folders at once.

Project numbers are stable references, not a strict execution order. New items keep new numbers even when placed before an earlier-numbered consumer.

Keep **Checkpoints** last as other items are added, removed or reordered.

Check an item when its work is completed and accepted. A prepared folder is separate from completed work. Keep detailed evidence and implementation records in the owning project folder and link the result here. This checklist holds the overall concept; it does not dispatch work or replace the Mission Control setup TODO.
