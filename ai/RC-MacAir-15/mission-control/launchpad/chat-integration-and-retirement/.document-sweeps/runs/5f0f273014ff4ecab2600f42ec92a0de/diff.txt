+### 4.1 Begin, prepare, commit
+
+The existing action boundary exposes a compose-only material operation with a begin snapshot and one commit result. +1. **Begin synchronously at material action start.** Global caller resolves the current active open mounted chat; composer caller supplies its explicit committed owner. Capture immutable `workspaceId`, `viewId`, `threadGroupId`, `threadId`, `surfaceId`, host/binding kind, mount lifetime generation and, for Side, exact placement identity. Capture workspace activation/hydration generation as needed to prevent leaving/returning from reviving a cancelled operation. Do not invent durable/session IDs.
+2. **Validate before source preparation.** No valid owner means a bounded unavailable result and no source work, draft/attachment mutation, Send, new chat or fallback. Missing/unhydrated/foreign tuples do not become valid from `currentThreadId` or an attachment path.
+3. **Source prepares independently.** Supply its captured request inputs/socket/resource root/workspace; it returns text or one existing `ChatLinkAttachment`. Capture/save, clipboard lookup, recents selection, transcription and diagnostic validation stay source-owned. No source writes pending attachments/drafts or resolves a replacement destination after await.
+4. **Revalidate immediately before mutation.** The shared owner checks the captured tuple/token, current hydrated authority, session existence, exact Side placement if applicable, source cancellation and applicable existing acceptance gate. It never re-resolves global focus. The check and local store mutation execute in one synchronous commit path; no intervening await creates another identity race.
+5. **Insert through existing stores once.** Text writes only the captured session's draft through `setDraft`; attachments use `addPendingAttachment`, preserving deterministic IDs, order, deduplication and generation semantics. The result distinguishes applied/no-op duplicate, cancelled, unavailable/busy, invalid material and source failure so callers do not claim a failed insertion succeeded. No retry into a different chat.
+6. **Presentation follows the result.** Source-specific success/failure statuses remain concise. Focus/caret restoration occurs only through the originating live presentation adapter and never steals focus from a newly active different chat/view. Store subscribers render exact-owner text/pills; controller touches no DOM.

+Preserve composer cursor insertion/replacement for clipboard/recents/microphone text and paragraph append for global/diagnostic text.
