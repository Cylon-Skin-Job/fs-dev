## Independent high-risk source traces

1. **Authenticated send versus queue admission.** `fusion-studio-client/src/lib/shell-auth-client.ts` returns true for a native send or retained pre-auth frame, and catches native send exceptions into false. Authentication activation installs the socket, delivers buffered initialization, then sets the final authenticated phase and flushes the outbound queue. `ws-client.ts:284–322` and `:454–455` connect that sequence to workspace initialization and receipt recovery. The candidate preserves the valid-binding recovery queue case while retaining socket-only admission for the prompt/raw callers. It neither equates queue admission with acceptance nor rejects recovery solely because asynchronous `hasReceivedInit` projection is unfinished.
2. **Truthful local failure.** `chatSlice.ts:344–386` already returns rich prompt outcomes based on its local send observation. C2 moves classification below the authenticator's information-losing catch, separates serialization/refusal from possible transmission, and explicitly leaves unavailable/unprovable evidence uncertain. All results remain local transport observations. Original prompt acceptance stays with server `message:sent`, and uncertain mutation listeners survive for authoritative responses.
3. **Concrete recovery defect and bounded correction.** `prompt-submission-recovery.ts` uses a void sender, ignores returned false and arms a five-second timeout. Timeout clears `inFlightGeneration`; the response handler requires it, dropping an otherwise matching late reply. C3 specifies prompt feedback on definite refusal, separate waiting and response eligibility, preservation after timeout/exhaustion or later refusal, exact identity fences and post-send currentness checks. Both acceptance and execution watches retain existing presentation and retry timing. The original prompt is never resent, cancelled or rejected merely because a status inquiry fails.
4. **Binding retirement.** `workspaceStore.ts:164–178` clears epoch/revision in `beginInit` while retaining visible workspace ID. Current recovery's panel subscription checks only ID changes. The candidate explicitly requires admission/flush checks and recovery retirement on epoch/revision invalidation, including same-ID rebind and A→B→A. Native receive currentness and server workspace-operation ordering remain separate defenses.
5. **Server ownership and later repair.** Router ingress checks bounded frame/type, diagnostic-prefix precedence and trusted metadata authority. Its prompt path validates request/config, captures binding, enters the workspace lease and same-attempt lock before runtime admission. Stop/response use captured provider ownership; close delegates cleanup without a second kill. `prompt-submission-service.js` owns cancellation fencing, atomic acceptance/activity and dispatch projection, including claimed→unknown.
