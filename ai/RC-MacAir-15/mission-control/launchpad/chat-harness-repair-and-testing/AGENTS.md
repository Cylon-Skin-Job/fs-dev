This is an owner-selected Launchpad memory home for follow-on OpenCode harness work. Repository and parent Mission Control instructions apply.

## Scope and authority

Own the discussion, evidence and later assigned OpenCode harness repair/testing after the current last-build job is finished. [Integration and Retirement](../chat-integration-and-retirement/TICKET.md) retains that job, including necessary repairs, verification and its existing acceptance requirements. Detailed follow-on repair scope and acceptance scenarios remain to be settled here; follow [INTENT](INTENT.md) and [DECISIONS](DECISIONS.md).

## Main and side roles

The owner designates one fronting main session. Shared CWD or inherited history does not transfer another task's identity or assignment. Bounded side chats follow their explicit scope, preserve other edits, return evidence and do not delegate or register as the main. A replacement verifies its predecessor is inactive and receives an explicit handoff.

Use the local [Launchpad procedure](../.agents/skills/mc-launchpad/SKILL.md), [ticket workflow](../../ticket-workflow.md) and [investigation contract](../../investigation-contract.md) within actual assignment authority. Main-session investigator authority under the shared contract does not apply to this provisioning chat.

## Main-chat startup

Follow the installed Launchpad folder-startup contract and [conversation evidence rules](../../conversation-evidence.md). Verify main identity through trusted runtime metadata and built-in task reads before registration. Preserve an existing CHECKPOINT.json identity/boundary; replacement requires explicit handoff. Side chats do not create or rebind checkpoint state.

## Boundaries

Provisioning does not dispatch/resume investigation, implementation, a roadmap, a task, monitoring, Git publication or Alpha operations. Current-build closeout precedes broader harness work. Preserve existing SPECs, evidence, acceptance and task ownership. Other proposed chat projects retain their separate scope.

Before changing chat/thread/harness behavior, read the current [Chat wiki overview](../../../Wiki/007-Chat_System/000-Overview_and_References/PAGE.md). Record a separate implementation checkout when assigned; this folder is the memory home.

## Reports and handoff

Preserve source-native IDs, revisions, last-check versus last-progress times, and reported versus verified outcomes. One writer owns each shared target. Bulletin entries are advisory, not delivery or approval. Sign bounded side contributions as Codex side chat (ephemeral) with an ISO UTC timestamp. Return sources, changed files, checks, remaining questions and the next safe action.
