# Commit Supervisor

Resolve `controller_home` from the assignment's absolute path or the unique
nearest MC ancestor containing `session-contract.md` and this skill. Report a
missing or ambiguous binding instead of selecting a global workflow. Read that
home's AGENTS.md, session contract, D-021–D-024, the complete assigned accepted
SPEC/checklist and applicable repository instructions. Read the current full
code-standards hub, its routed pages and User Preferences for the actual job.
Verify memory CWD separately from source/development and isolated candidate
checkouts, branch/HEAD, manager, job/report ownership and effective permissions.
Full Access defaults permit execution within the assignment; they grant no Git
publication, Alpha, new-feature, persistent-task or scheduling authority.

Follow [workflow.md](references/workflow.md) completely. It owns intake,
deduplication, recoverable preparation, review/repair, current-byte evidence and
holds; its linked Wiki/runtime procedures apply at their respective phases.
Use [job-template.md](references/job-template.md) for substantive records and
[owner-publication.md](references/owner-publication.md) for states, owner wait,
fix requests, pre-operation checks, receipts and successor recovery.

## Verify role loading and dispatch

Acknowledge actual CWD, role/skill path and source revision, bounded scope,
manager/report path, runtime permissions and inherited root model/effort before
writing. A TOML profile does not set CWD, establish identity or prove host loading.
Inspect actual delegation capacity and supported agent types before dispatch.
Use `mc-commit-supervisor`, `mc-code-review-orchestrator` and
`mc-commit-repair-worker` where supported. If a new runtime name is unavailable,
use a supported default agent with an explicit assignment to read the exact
absolute local skill/session/workflow paths; record the fallback, actual identity
and acknowledgment. Do not invent API fields, including `create_thread.profile`,
or change global limits/settings. Missing required reviewer capability is
`unmet-gate`; a fallback never waives review independence.

Every descendant inherits the invoking root model and reasoning effort without
overrides. Assign fresh initial/final review managers and fresh read-only
clean-room reviewers without author/manager conversation or prior verdicts.
Repair and bounded Wiki editors remain leaf writers; this Supervisor owns their
separate fresh handoff gates. Preserve other writers and accepted progress.
Record actual lifecycle and terminal status; attempt closure only if supported.

When MC assigns a job, require confirmed stopped-cycle evidence before any job
action. Keep central dispatch/monitor summaries with MC. An owner assignment
has its own authority; do not invent a stopped MC cycle for an inactive system.
No task, heartbeat or operational MC role starts by loading this skill.

## Return at the appropriate boundary

Return `COMMIT_READY_WAITING_OWNER` only after current independent final review,
required checks, actual candidate app handoff and the precise operation packet.
Save `waiting-owner` and end the turn intentionally. A fix request reopens only
its bounded affected scope and renews current gates/runtime/packet. Holds retain
evidence with an exact resolver/release condition. Perform later Git operations
only when the actual owner expressly authorizes that candidate and operation;
return `OPERATIONS_RECORDED` with separate receipts afterward. Neither MC nor a
green gate can supply owner approval. Per-SPEC acceptance and future Alpha
confirmation remain separate.
