## Ownership Zones

- Hand-written prose is everything outside the `<!-- section-toc -->` markers. Edit freely.
- Marker blocks are script-owned. Never hand-edit them; run the sync script instead.

## Article Versions

Every article folder may contain a hidden `.versions/` folder beside its `PAGE.md`:

```text
001-Article_Name/
├── PAGE.md
└── .versions/
    └── YYYY-MM-DD-HHMMSS.md
```

- A version file is a complete copy of the article's `PAGE.md` at that moment.
- Use the local timestamp format `YYYY-MM-DD-HHMMSS.md`. The containing article folder identifies the source, so version filenames do not need descriptions.
- Create a version before a substantive article rewrite. Typo fixes and generated TOC-only changes do not require one.
- `.versions/` applies at every level of the wiki hierarchy wherever a `PAGE.md` exists.
- Never create versions of files already inside `.versions/`.
- The dot-prefixed folder is intentionally absent from normal wiki navigation and generated contents blocks.
- Git remains the authoritative repository history. Article versions provide a nearby, simple baseline for inspection and restoration.

## Moves And Renames

Renaming or renumbering folders changes paths. Before moving:

1. Find every reference to the old path — wiki links, `AGENTS.md`, workflow pages.
2. Update references and move together. Marker-block links fix themselves on the next script run; hand-written links do not.

## Source Files And Modification Time

Follow the [Wiki Style Guide](../001-Style_Guide/PAGE.md#frontmatter-contract): maintain `metadata.source-files` and a quoted UTC `metadata.last-modified` timestamp. Do not maintain edge, connected-skill, or related-trigger lists. When adopting the schema on an edited page, remove those legacy keys; preserve ordinary body links and unrelated domain-owned metadata.

Update source paths when their owning code moves, and check that they still describe the page's subject. Set `last-modified` to the actual write time for any page-content change, including metadata, typo fixes, and generated-block changes. Preserve it on no-op reads/reviews and byte-preserving moves. The timestamp is not a verification date. Do not fabricate dates for untouched older pages or reset timestamps in `.versions/` copies.

Current editor/audit code does not automatically maintain this new field. After a generator changes a page, stamp that page's authored frontmatter; do not manually alter its generated block. A no-op generator run does not require a new timestamp.

## After Structural Changes

Run `node fusion-studio-server/scripts/wiki.js audit /path/to/workspace` and read its output. The audit can also create legacy TOC pages with the old metadata envelope; normalize those newly written pages to the current style guide and stamp their actual edit time. Do not migrate unrelated untouched pages. `updated` lines confirm blocks regenerated; `skipped (no-markers)` lines are the remaining migration worklist.
