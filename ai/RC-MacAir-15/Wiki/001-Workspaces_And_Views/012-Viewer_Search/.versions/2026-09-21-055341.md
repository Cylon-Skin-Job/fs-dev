This is **local viewer search** in current folder-backed Capture and Office React views. It is neither web search in [Browser](../005-Browser/PAGE.md) nor a universal search facility supplied to every future view plugin. The server serves file trees and content; the client builds and ranks the index. [View Architecture](../002-View_Architecture/PAGE.md) explains the current built-in renderer boundary.

## Shared current mechanics

`useViewerSearchIndex.ts` requests configured root trees through `fileDataStore`, optionally traverses child folders, asks for file content where the adapter permits it, and ranks folder/file fields through `searchQuery.ts`. The query parser supports case-insensitive terms, implicit AND, explicit AND/OR/NOT, quoted phrases and parentheses. Ranking favors title before location and body. `ViewerSearchField` calls its submit handler on Enter; changing the input alone does not submit a new search.

`ViewerSearchFilters.tsx` renders Type, Modified, Location, Title only and optional Starred only controls. Its local controls do not by themselves establish filtering of ranked results. Check each view adapter's actual wiring before describing a filter as functional.

## View-specific scope

Capture's `useCaptureViewerSearch.ts` uses the ordered Capture folders passed by its host, including the archive root used by Capture search. It returns file matches, not folder results; images use title/location without body loading. Office's `useOfficeViewerSearch.ts` starts at the Office root plus Archive, traverses nested folders and includes matching folders as results; images likewise skip body loading. Both adapters reuse the same index but determine their own roots and eligibility. [Server And Runtime](../../002-Server_And_Runtime/PAGE.md#current-view-path-runtime) records path resolution and normal-listing archive hiding.

A new plugin-defined view may choose a different content model or search implementation. The approved plugin direction does not imply that all plugin views inherit this React hook, client cache or query grammar. Future shared search requires an explicit interface and capability design, not a copied claim from these two built-ins.
