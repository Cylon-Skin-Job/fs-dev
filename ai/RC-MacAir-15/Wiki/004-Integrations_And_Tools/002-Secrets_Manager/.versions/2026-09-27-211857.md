Use **Tools → Secrets Manager** to register a manual API key or token by name and description. The description helps distinguish similarly named slots. Do not paste a value into chat.

## Current storage and discovery

The current API-key backend stores values in macOS Keychain under the `fusion-studio` account. `fusion.db` stores `secrets_index` metadata: name, description, optional expiry, fingerprint and timestamps. Listing entries returns metadata, not values. Names begin with a letter and contain uppercase letters, digits or underscores; descriptions are limited to 150 characters. An absent list entry means no registered index row for that name, not proof about unrelated Keychain items. The historical `ROBIN_DB` environment variable remains in server startup but is omitted from the production harness child-environment allowlist, so the former agent-side SQLite command is not a supported discovery recipe.

## Safe use and failures

Keep credential values out of chat, tickets, logs, model-visible tool results and generated files. The current Secrets Manager WebSocket diagnostics redact the value field, and the renderer lists metadata. Those specific safeguards do not establish universal protection for arbitrary shell commands, process arguments, environment, tracing, failures or provider responses. A reviewed agent retrieval interface remains open product work in [RCC-0094](../../../Issues/inbox/RCC-0094.md). If the available route cannot meet the task's exposure boundary, explain the limitation and direct the user to the app's credential entry path.

If a slot is absent, identify its intended name and purpose. If metadata exists but the value cannot be read, distinguish a missing Keychain item, locked or denied Keychain and backend failure. An empty or stale UI list is not by itself a successful Keychain lookup: the globally mounted modal currently lacks fresh list hydration on open, and raw Keychain errors are not consistently mapped to its backend-unavailable state. Never infer that a failed lookup proves the user lacks a credential.

## Metadata and future platform support

`expires_at` is an optional Unix millisecond timestamp displayed as a date. The current UI does not implement the old page's proactive one-week warning. A fingerprint shows twelve bullets and the last four value characters; it is display metadata, not a reason to disclose suffixes broadly. Electron `safeStorage`, cross-platform storage and background agent retrieval are proposed in RCC-0094, not the current backend. Ordinary clipboard copying is not credential storage; [Frontend UI Standards](../../005-Enforcement/001-Code_Standards/002-Frontend_UI/PAGE.md) owns copy behavior.
