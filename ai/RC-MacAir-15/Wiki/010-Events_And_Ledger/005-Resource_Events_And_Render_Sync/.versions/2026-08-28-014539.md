Use this page before changing file-change events, view cache invalidation, or Wiki/File Viewer refresh behavior.

Resource/render sync should consume canonical UEB resource events and update central cache/state. Views should subscribe to state and render from it. They should not each own private WebSocket listeners, recursive reload policies, or stale-check loops.

First-package workspace/view/theme lifecycle events use `lifecycle-metadata-v1` version `'1'`. Canonical workspace-switch records contain workspace IDs and reason, never absolute/local roots. View/theme affected paths are canonical workspace-relative. Compatibility roots, broad context/resources/ledger fields, actor ID, and source filesystem paths are omitted; unknown fields error. Lifecycle status `failed` is not canonical and has no safe core. Policy failure preserves the lifecycle operation and invokes non-canonical `lifecycle:refresh_required` with workspace, view-registry, or theme scope.

## Target Flow

```text
file/folder mutation
  -> successful owning mutation
  -> resource event candidate
  -> validation + canonical admission / diagnostic gate
  -> accepted canonical resource event
  -> resource sync subscriber
  -> renderer resource message
  -> central cache invalidation
  -> view selector updates
  -> React reconciliation
```

Mutation resource facts, admission, and renderer projection occur only after the owning mutation succeeds; watcher resource facts begin only after the observation safely establishes workspace/path/operation. Resource sync acts on accepted canonical events. Malformed candidates produce diagnostics rather than being treated as canonical. Optional attribution/enrichment never suppresses an otherwise valid workspace/path/operation fact. If unexpected publication or projection failure after either branch would leave the UI stale, use conservative recovery plus a diagnostic without changing the mutation result or observed filesystem fact.

The recovery transport is the non-canonical `FreshnessRecoveryMessage` union: `resource:refresh_required` carries authoritative workspace/reason/path hints, while `lifecycle:refresh_required` carries nullable workspace, reason, lifecycle scope, and optional affected-panel hints. Candidate rejection, publisher failure, and suppression are pre-admission: no ref/delivery exists. Broadcaster projection failure is post-admission: the accepted ref/frozen event remain valid for every other subscriber and are not revoked. Both branches invoke the matching recovery variant. Clients preserve navigation/history/scroll/dirty/optimistic/undo state; clean entries replace, while dirty entries use `recoveryRemote` and `conflict_pending`. A null workspace switch detaches rather than discards dirty buffers. View-registry and theme recovery refetch their own state without clobbering user work. Recovery never enters UEB.

Immediate resource mapping uses no live registry lookup. Before admission the producer deep-freezes the current resource-policy generation; after true publication it stores that snapshot in a private WeakMap keyed by `acceptedRef` before queued listeners can run. The subscriber reads it only through `(frozenEvent, { acceptedRef })`; policy reload affects future events, not queued ones. Missing sidecar means projection failure/recovery without revoking admission.

Lifecycle renderer messages are an exact discriminated union: workspace switch pairs `workspace.switched` / `workspace-switch` / `workspace` / `all`; view registry pairs `view.registry_changed` / `view-registry-change` / `view-registry` / `registry`; theme pairs `theme.changed` / `theme-change` / `theme` / `style`. The accepted frozen event is the only construction input: renderer `eventId` and `ids` must match it exactly. `ids.workspaceId` and, only for a workspace switch, required `ids.previousWorkspaceId` are the only workspace identities. Cross-paired event types, IDs, scopes, actions, kinds, or extra top-level workspace identity are invalid.

Receiver routing is separate private state. First-package lifecycle publication is connection-originated and installs a frozen `AcceptedCanonicalRef`-keyed route sidecar containing opaque initiating-connection and lifecycle-epoch capabilities plus the post-switch workspace before listener tasks can run. Delivery/recovery rechecks that the initiator's epoch and workspace are still current; an older queued transition is diagnosed and cannot invalidate or rewarm the initiator's newer state. Null-workspace invalidation/recovery resolves only that current opaque initiator, never all connections whose workspace is null; non-null routing adds only connections whose authoritative workspace matches at delivery. The sidecar exposes no connection or epoch ID and is never canonical, serialized, or persisted. Installation failure triggers direct producer-owned recovery only while the captured route is current; the missing-sidecar subscriber branch diagnoses without duplicating recovery. Headless/global lifecycle publication remains unregistered until its routing and recovery semantics are approved.

Canonical `workspace:switched` publication is gated on the SPEC-32b0 operational sequencer/topic fence. Generic EventBus listeners are unawaited, so every active switch/create/remove/ribbon ingress synchronously enqueues one intent before lookup or active-state reads. A single workspace coordinator resolves intents FIFO, captures `from` from the last commit, transactionally commits active registry/settings changes, updates memory only after commit, and sends the exact adjacent pair plus opaque ordered capability through a closed registry of audited bounded synchronous hooks that reject thenable returns. Synchronous I/O, unbounded CPU, user/plugin callbacks, and reentrant mutations are prohibited because an in-process function that never returns cannot be recovered. Controller/ribbon code cannot write active state or emit switches directly. The coordinator owns authoritative workspace/root resolution; per-session cache failure forces recomputation/snapshot rather than leaving A authoritative. The baseline broadcaster has no async enrichment/serialized queue and is at-most-once: healthy delivery sends exactly one `type: 'workspace:switched'`, while failure records a diagnostic and relies on reconnect authoritative snapshot plus `lifecycle:refresh_required` without retrying the pair. The watcher hook invalidates/installs synchronously and supervises detached close/ready/reconciliation without holding the FIFO. Hook throws, returned thenables, and detached background failure/nonsettlement cannot roll back the committed workspace, invoke provenance, or block the next intent. This workspace-owned transport remains noncanonical and unpersisted after 40b1b. The old ledger whitelist stops recording workspace switches, and legacy persistence pauses until SPEC-35. After accepted 32b/32c/40b1b, canonical `workspace.switched` independently carries the registered envelope to accepted-only subscribers and the separate `resource:invalidate` freshness path; only its durable row remains gated on SPEC-35. Concurrent-request/failure tests prove one total order, adjacent pairs, database/memory/coordinator-resolver/watcher-generation consistency, healthy exactly-one notification, recovery after failure, and no canonical lifecycle row before SPEC-35.

The active first-package canonical workspace producers are the live-connection `switch_requested`, successful create/activate, active remove fallback/null, active ribbon remove fallback/null, and ribbon add from null branches; all map exactly to `workspace.reason = 'user_switch'`. `ids.previousWorkspaceId` and `ids.workspaceId` are both required-nullable and jointly identify the transition. WebSocket ingress resolves an opaque route capability and enqueues it with the intent; only the coordinator head captures the authoritative pre-operation workspace, and the lifecycle epoch binds the exact committed/settled previous/current pair. Admission rejects missing or mismatched prior state even when the post workspace matches. Invalid/no-op/non-active changes emit no lifecycle fact. `startup|reload|system` remain schema-reserved but unauthorized until a registry update names and tests an exact connection-bound producer; initiator-absent/headless publication remains out of scope. Missing route capability omits only canonical lifecycle provenance with a diagnostic and never blocks the operational switch.

Workspace watcher and TRIGGERS.md filter lifecycle is a synchronous hook of the permanent private `workspace:operational_switched` coordinator dispatcher, not canonical lifecycle admission or generic EventBus ordering. Slice 32e is blocked until owner decision `RSC-D16` approves the exact close-diagnostic/readiness/reconciliation watchdog values and semantics. The hook verifies the next ordered capability/pair, invalidates the prior generation, installs B/null bindings/listeners, launches supervised close/ready/reconciliation plus watchdogs, and returns a non-Promise acknowledgment. Those tasks/timers check currency; throw or expiry cannot block the next workspace intent, current ready/reconciliation failure enters `degraded_recovery_pending` with exactly one freshness recovery, and close expiry only diagnoses cleanup. A later transition cancels/invalidates them. File-change trigger matching consumes only its single established workspace-watcher observation path; mutation handlers do not invoke a second matcher. It never awaits canonical resource admission. While `AUT-D02` is open, canonical file-trigger automation facts omit direct resource IDs/edges; after closure only its approved non-wait accepted-ref handoff may bind them. Provenance failure cannot suppress or duplicate operational trigger execution.

The operational matcher accepts only this closed current watcher-condition vocabulary: `filePath`, `parentDir`, `type`, `ext`, `basename`, `delta`, `oldPath`, `newPath`, `parentStats.files|folders`, and `fileStats.lines|words|tokens|size`. The exhaustive lexer is owned by SPEC-32: 512 UTF-8 bytes overall; numeric keys use signed safe base-10 integers without plus/negative-zero/leading-zero/float/exponent; string keys use equality/inequality with a 256-byte quote-without-escapes value or `[A-Za-z0-9_./:@*-]+`; the three nullable keys also accept exact null. Operators parse longest-first and the full input is consumed. Watcher stats are operational trigger context, not canonical provenance enrichment. Slice 32e side-effect-free parses/classifies all blocks but validates/reloads only file-change blocks through atomic `replaceFilters`; cron and bus triggers retain one-time registration and cannot be duplicated/removed by workspace reload. Workspace parse failure installs no old-root filters; same-workspace fatal reload retains the last valid set. Invalid file syntax never defaults true. Post-execution provenance may use valid metadata only for correlation.

File-change blocks also use SPEC-32's closed schema. Slice 32d only preserves the single current matcher; Slice 32e exclusively introduces and owns lifecycle repoint/recompile. It loads immutable declarative/programmatic base descriptors once, then instantiates both base and trigger filters per controller-owned generation capability with an opaque bound workspace root and currency guard. At the synchronous transition linearization point, after authoritative workspace selection and before any await, B/null becomes current and A is permanently invalidated. Programmatic filters with workspace side effects are generation factories. Actions recheck currency after every await/callback boundary and immediately before irreversible effects; stale callbacks/timers and obsolete reconciliation are no-ops. B handlers attach before transition awaits, settlement requires A close/B ready/current-generation reconciliation, and reconciliation never synthesizes trigger execution. Atomic replacement preserves each base descriptor once without retaining startup-root closures, replaces workspace trigger filters, and never touches cron/bus registrations. Tests prove every B action targets B and paused A callbacks cannot affect A or B after transition.

## Invalidation Rule

Invalidate the smallest affected resource: file content, parent folder tree, style resource, config resource, registry resource, or known dependent index. Do not clear a whole view unless the workspace/root changed or the active resource disappeared.
