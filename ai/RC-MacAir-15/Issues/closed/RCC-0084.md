Registered `fusion-studio://` as a privileged Electron protocol so iframes can load view files from the active workspace without CORS or security origin issues.

### URL structure

`fusion-studio://{viewId}/{relative/path/to/file}` resolves to `{activeWorkspace}/ai/<machine>/Views/{viewId}/{path}`

### What shipped

- `electron/protocol-handler.cjs` — `registerScheme()`, `registerHandler()`, `setWorkspaceRoot(repoPath)`
- Scheme privileges: `standard`, `secure`, `supportFetchAPI`, `corsEnabled`
- Path traversal guard: target must stay inside `viewRoot`
- `net.fetch(pathToFileURL(target))` pattern for MIME-correct file serving
- IPC: renderer sends `workspace:set-root` on `workspace:init` and `workspace:switched` to keep protocol handler in sync
- `activeRepoPath` added to `workspace:init` server message
- `window.electronAPI?.setWorkspaceRoot()` — optional chain safe in browser dev mode

### Files created / modified

- `electron/protocol-handler.cjs` (new)
- `electron/main.cjs` (updated — registerScheme before ready, registerHandler + IPC in whenReady)
- `electron/preload.cjs` (updated — setWorkspaceRoot exposed)
- `src/types/electron.d.ts` (updated — setWorkspaceRoot type)
- `fusion-studio-server/server.js` (updated — activeRepoPath in workspace:init)
- `src/lib/ws/workspace-handlers.ts` (updated — setWorkspaceRoot called in both handlers)
