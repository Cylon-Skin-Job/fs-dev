Document and fix the testing-structure confusion around Playwright, Electron, and the Fusion Home restart script.

Fusion Studio is an Electron app intended to be bundled, but the current Playwright configuration only tests the browser-served renderer/server path. Future sessions need a clear distinction between fast browser smoke tests and real Electron shell smoke tests.

## What Happened

During assistant reply chrome planning, Playwright was discussed as the UI verification path. The existing `fusion-studio-client/playwright.config.ts` was found to:

- run specs from `fusion-studio-client/e2e`
- use Chromium desktop
- open `http://localhost:3001`
- start `node ../fusion-studio-server/server.js` through Playwright `webServer`
- reuse an existing server when present
- run with `fullyParallel: true`

That setup is useful, but it does not launch Electron, does not exercise Electron main/preload behavior, and does not validate the app the way it will be bundled.

Separately, the repo owns the operational restart path:

```bash
/Users/rccurtrightjr./projects/fs-dev/restart-fusion.sh
```

That script builds the client, kills prior Fusion/Electron/server processes, launches Electron through macOS LaunchServices, waits for Electron's server port file, and prints the live server URL.

## Culprits

- The repo has a browser Playwright config, but no separate Electron Playwright config.
- The browser Playwright config name does not make clear that it is not Electron.
- Existing e2e specs include debug/diagnostic screenshot tests alongside stable assertion tests.
- `fullyParallel: true` is risky for app-state tests because Fusion uses shared server/workspace state.
- The restart script now lives at the `fs-dev` repo root, so future workers can discover it from repo-local search.
- Electron uses `FUSION_APP_USER_DATA` to control the app user-data path, but the test structure does not currently encode that isolation.

## Current Testing Shape

### Fast Browser/Server Smoke

Use for renderer/server assertions that do not require Electron APIs:

```bash
cd fusion-studio-client
npx playwright test <spec> --workers=1
```

Current config:

- `fusion-studio-client/playwright.config.ts`
- base URL: `http://localhost:3001`
- server command: `node ../fusion-studio-server/server.js`

Good for:

- DOM rendering checks
- WebSocket message flows
- disabled/enabled chrome states
- menu/modal layout checks in the browser renderer
- screenshots of browser UI

Not sufficient for:

- Electron main/preload IPC
- packaged resource path behavior
- Electron-owned server spawn
- app user-data behavior
- macOS window lifecycle behavior

### Electron Manual Smoke

Use for real app shell validation:

```bash
/Users/rccurtrightjr./projects/fs-dev/restart-fusion.sh
```

This is the current operational app restart path.

Good for:

- final visual validation
- real Electron shell behavior
- confirming rebuilt renderer bundle is what the app loads
- Electron-owned server lifecycle

Gotchas:

- It opens a GUI app and may require approved/elevated execution.
- It can dirty runtime state such as workspace cache/state files.

## Target Testing Shape

Keep the browser Playwright path, but add a separate Electron Playwright lane.

Recommended files:

```text
fusion-studio-client/playwright.config.ts
fusion-studio-client/playwright.electron.config.ts
fusion-studio-client/e2e/
fusion-studio-client/e2e-electron/
```

Recommended scripts:

```json
{
  "test:e2e:web": "playwright test --workers=1",
  "test:e2e:electron": "npm run build && playwright test -c playwright.electron.config.ts"
}
```

Recommended Electron config shape:

```ts
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './e2e-electron',
  fullyParallel: false,
  workers: 1,
  reporter: 'list',
});
```

Recommended Electron test launch shape:

```ts
import { test, expect, _electron as electron } from '@playwright/test';

test('launches Fusion Electron shell', async ({}, testInfo) => {
  const app = await electron.launch({
    args: ['electron/main.cjs'],
    cwd: process.cwd(),
    env: {
      ...process.env,
      FUSION_APP_USER_DATA: testInfo.outputPath('user-data'),
      FUSION_LOCAL_MACHINE: 'playwright-e2e',
    },
  });

  const page = await app.firstWindow();
  await expect(page.locator('.rv-app-shell')).toBeVisible();

  await app.close();
});
```

## App Facts Future Sessions Need

- Fusion Studio is an Electron + React + Node app.
- The server is owned by Electron in the real app path.
- The browser Playwright config tests the server-renderer path only.
- Electron `main.cjs` honors `FUSION_APP_USER_DATA` and sets Electron `userData` accordingly.
- Electron writes the active server port to `server.port` inside the Electron user-data directory.
- The server also uses `FUSION_APP_USER_DATA` for packaged/user-data storage, including `server-data/fusion.db`.
- `FUSION_LOCAL_MACHINE` can isolate machine-scoped test identity.
- Browser UI tests should not run fully parallel when they mutate shared app/workspace state.

## Acceptance Criteria

- Documentation clearly separates browser/server Playwright tests from Electron app tests.
- The browser Playwright lane is renamed or documented as web/browser smoke.
- App-state Playwright tests run with `--workers=1` or config-level single worker.
- A dedicated Electron Playwright config exists.
- Electron Playwright tests use isolated `FUSION_APP_USER_DATA`.
- Package scripts expose both web and Electron e2e commands.
- `restart-fusion.sh` at the repo root is documented as the manual Electron smoke path.
- Future feature specs know which checks belong in browser Playwright and which require Electron.
