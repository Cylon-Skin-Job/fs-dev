The old background-agent execution path is dead code. It is not booted, and it is built on the retired Kimi `--wire` harness. The trigger system replaced the buried ticket-monitoring it implemented. This ticket tracks removing it so the codebase stops implying a mechanism that no longer exists.

Found while documenting the background-agents wiki page.

---

## Dead / Orphaned Code

- `fusion-studio-server/lib/runner/wire-session.js` — spawns `kimi --wire --yolo`. The Kimi wire runtime path was removed from chat; this is the only remaining caller of that protocol. `wire-session` is not imported anywhere outside the `runner` module.
- `fusion-studio-server/lib/runner/` (`index.js` `executeRun`, `heartbeat.js`, `prompt-builder.js`, `run-folder.js`) — the agent run engine. `executeRun` is only reached through `tickets/dispatch.js`, which is not booted (see below).
- `fusion-studio-server/lib/tickets/dispatch.js` `startDispatchWatcher` — the ticket→agent dispatch loop. **Nothing in `startup.js` or `server.js` starts it.** It only runs via the file's own `if (require.main === module)` CLI entry point. So in the running app it never executes.
- `heartbeat` monitor wiring: `startup.js` calls `checkHeartbeats` from `./runner`; confirm whether it still needs to after the runner is removed.

## Path Mismatch To Resolve (if any of this is revived instead of removed)

- `lib/tickets/dispatch.js` and `lib/sync/pull.js` reference `issues-viewer/tickets.json` (view root), but the real render index is `issues-viewer/content/tickets.json`. If the dispatch/sync paths are ever revived they must point at `content/tickets.json`.

## What Needs to Happen

1. Confirm nothing user-facing depends on the runner/dispatch path (it is unbooted and wire-based).
2. Remove `lib/runner/` and `startDispatchWatcher`, or quarantine them clearly as retired.
3. Clean up the `startup.js` heartbeat require if it dangles after removal.
4. Grep for any remaining `--wire` / `kimi` references in server code and remove.

## Verification

- `grep -rn "wire-session\|--wire\|startDispatchWatcher" fusion-studio-server/lib` returns nothing after cleanup.
- Server boots and chat (OpenCode) is unaffected.
