Build a composable Send to Chat action primitive that any feature panel, settings row, system control, resource view, or workflow surface can use to preload chat with a command, skill, prompt, or resource reference.

This generalizes the existing Send to Chat button behavior. It should support both sending/preloading into the current chat and spawning a new chat with a preloaded workflow.

## Goal

Make chat-driven configuration and workflow launchers a reusable UI/action pattern.

Examples:

- Existing resource buttons that send a file/path to chat.
- Settings rows that launch assistant-supervised changes.
- System panels that need a workflow instead of direct mutation.
- Future "Rename This Machine" action that starts `/rename-user-machine`.
- Other workflow shortcuts that preload a skill into chat.

## Action Contract

Use a shared action shape:

```text
prompt: string
spawn_new: true | false
label: optional string
title: optional tooltip/accessibility label
metadata: optional object
```

`spawn_new: false`:

- Use the existing chat context.
- Use the normal Send to Chat icon: `chat_paste_go`.
- UI may be icon-only when the action is compact or already obvious.
- Preserve existing Send to Chat behavior where it already exists.

`spawn_new: true`:

- Create/start a new chat/thread.
- Preload the prompt into that new chat.
- Use the new-chat Send to Chat icon: `chat_paste_go_2`, which shows an empty bubble.
- Render as an icon plus text button when used as a larger workflow launcher.
- Use the app's system button theming behavior.

## UI Pattern

Compact existing usage:

```text
[chat_paste_go]
```

Workflow-launch usage:

```text
[chat_paste_go_2 Rename This Machine]
```

The machine rename example is not a one-off. It is the first expected consumer of a reusable pattern.

## First Consumer Example

A local machine settings panel can show the current machine name. Its edit action should not directly mutate the internal DB or rename folders.

Instead:

```text
prompt: /rename-user-machine
spawn_new: true
label: Rename This Machine
icon: chat_paste_go_2
```

The spawned chat workflow can ask the user for the desired new name, whether to rename or clone `ai/<machine-name>/`, and whether to apply matching folder updates across other workspaces.

## Scope

- Find current Send to Chat components/helpers and extract the reusable behavior.
- Add a shared action component/helper that accepts `prompt`, `spawn_new`, label/title, and optional metadata.
- Keep existing icon-only Send to Chat buttons working.
- Add support for spawning a new chat/thread and preloading the prompt.
- Use `chat_paste_go` for existing/current-chat actions.
- Use `chat_paste_go_2` for new-chat workflow actions.
- Apply system button theming to text-bearing workflow buttons.
- Add the first usage hook or placeholder for future settings/system panels.

## Out Of Scope

- Implementing `/rename-user-machine`.
- Renaming machine folders.
- Changing local machine DB schema.
- Building the full settings panel.
- Designing every future workflow button.

## Smoke Tests

- Existing Send to Chat path/resource buttons still paste/send into the current chat.
- A `spawn_new: false` action renders as an icon-only `chat_paste_go` button when no label is supplied.
- A `spawn_new: true` action renders as a system-themed icon+text button using `chat_paste_go_2`.
- Clicking a `spawn_new: true` action creates a new chat/thread and preloads the configured prompt.
- The "Rename This Machine" example can be represented entirely by the shared action contract.

## Dependencies / Gotchas

- Coordinate with the chat/thread creation path so a new thread is ready before prompt preload.
- Preserve focus behavior: after click, focus should land in the target chat input.
- Avoid accidental immediate execution if the intended behavior is preload-only. If submit-on-click is later needed, add a separate explicit option rather than overloading `spawn_new`.
- Keep this action independent of any single settings panel so it remains reusable across the app.
