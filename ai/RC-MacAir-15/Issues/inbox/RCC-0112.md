Polish the visual transition when a user returns to a thread whose assistant turn advanced while off-screen, after RCC-0108 has implemented the authoritative stream-frontier correctness contract.

## Parent And Dependency

This is a follow-up to [RCC-0108 — Handle empty/opaque thinking blocks in chat streaming UI](RCC-0108.md).

RCC-0108 remains responsible for the non-negotiable behavior:

- `LiveTurnSnapshot.streamSeq` is the authoritative whole-turn stream frontier.
- A completed or terminal turn renders immediately when reopened.
- An in-flight snapshot through sequence `N` is installed as an already-revealed baseline.
- Only mutations after `N` animate.
- Snapshot/live-message races create no gaps, duplicates, or regressions.

This ticket may begin after that contract is implemented and covered by deterministic tests. It must not replace, weaken, or redesign the server ownership, routing, sequence, persistence, or catch-up rules approved in RCC-0108.

## Deferred Work

Decide and implement the exact cosmetic treatment at the boundary between the instant snapshot baseline and newly arriving live output. Candidate details include:

- whether the newest partial text or thinking segment receives a brief fade or other continuity treatment;
- how an already-present active tool row transitions into later tool progress or results;
- easing and duration for the catch-up boundary;
- visual continuity when the user switches away and back repeatedly during one turn;
- reduced-motion behavior for any newly introduced transition;
- whether different segment types need distinct polish while preserving one shared frontier rule.

Prefer restrained continuity cues. Do not replay the off-screen backlog to make the transition look animated.

## Likely Code Surface

- `fusion-studio-client/src/components/LiveSegmentRenderer.tsx`
- the pure live text/tool presentation children already owned by that renderer
- focused chat renderer styles and Playwright coverage

Honor the Code Standards' explicit `LiveSegmentRenderer.tsx — DO NOT SPLIT` completion-pipeline decision. A pure presentation child may be added only if it does not divide the renderer's sequential reveal and exactly-once completion ownership.

## Acceptance Criteria

- RCC-0108's frontier, routing, persistence, and no-replay tests remain unchanged and passing.
- Returning to an in-flight thread has a deliberate, visually continuous transition from the instant baseline to genuinely new output.
- Completed or terminal turns remain instant and never replay historical live animation.
- No cosmetic effect delays current content, alters `streamSeq`, changes message ordering, or introduces duplicate rendering.
- Repeated thread switching does not reset animation ownership or restart previously accepted content.
- Reduced-motion users receive an immediate, stable transition without newly introduced motion.
- Focused Playwright coverage and the client build pass.

## Non-Goals

- Changing `ThreadRuntimeManager` ownership or drain identity.
- Introducing another stream revision or replacing `streamSeq`.
- Changing snapshot hydration, event buffering, deduplication, or durable save correlation.
- Replaying off-screen output from the point where the user left.
- Redesigning the general chat renderer or tool presentation system.
