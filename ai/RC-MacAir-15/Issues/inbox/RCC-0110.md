Design the Open Router hooks policy surface for controlling which tool actions are allowed, blocked, or require explicit user confirmation before execution.

## Tool Block List

- [ ] External symlinks — block AI/tool-created inbound symlinks that point from inside the active repo to outside-repo targets unless a future explicit user permission flow allows it. Do not block reading, listing, grepping, or editing user-created symlinks. Outward symlinks that publish repo-owned resources to an external location require explicit user intent and should be handled through a dedicated permissioned action.

## Notes

This ticket came out of SPEC-31 symlink policy work. The intended boundary is on symlink creation/addition, not read/use: once a symlink exists in the workspace, Fusion Studio and AI can treat it as a real resource. Open Router Hooks should prevent AI from creating unsafe inbound external symlinks, while user-requested outward symlinks can publish app-created canonical resources outside the repo.
