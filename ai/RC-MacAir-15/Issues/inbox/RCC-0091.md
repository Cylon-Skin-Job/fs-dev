Redesign the Issues viewer around multiple issue sources.

## Owner direction — 2026-09-21

The normal-view iframe migration is retired. Iframe support exists as **Custom View**; normal Fusion Studio views will not migrate to iframes.

The target architecture is to extract normal views' reusable parts into **system modules**. Those modules can be bundled and curated into **plugins**. View folders become configurations pointing to installed plugins and holding the view's state and theming.

This records product direction, not a claim that the module/plugin transition is implemented. The existing built-in React Issues viewer remains the current implementation. Its source-tab and board requirements below remain open. Plugin architecture work must coordinate those boundaries; this ticket does not independently define a competing plugin system.

The Issues viewer should support local machine tickets, remote API-backed GitHub/GitLab issues, and read/browse access to other synced machine issue folders under the new `ai/<machine>/` workspace paradigm.

**Historical template reference:** [AI Workspace Template V2](../../Captures/999-Archive/AI_WORKSPACE_TEMPLATE_V2_SPEC.md). Its archived implementation recipes do not override the owner direction above.

---

## What Needs to Happen

1. **Follow the system-module/plugin view boundary**
   - Reserve iframe hosting for Custom View; do not migrate normal Issues-viewer parts into an iframe.
   - Normal-view parts become system modules that can be bundled and curated into plugins.
   - View folders configure installed plugins and retain state and theming.
   - Coordinate module/plugin integration with its owning architecture work; preserve the current built-in React implementation until that transition is delivered.

2. **Add source tabs**
   - `Local` — local machine issues from the configured `ai/<local-machine>/Issues/` folder.
   - `GitHub` — GitHub issues loaded fresh through the GitHub API.
   - `GitLab` — GitLab issues loaded fresh through the GitLab API.
   - Other machine tabs — one tab per synced `ai/<machine>/Issues/` folder found in the repo.

3. **Local tab behavior**
   - Local tickets are filesystem/local workflow state for this machine only.
   - Local tickets can drive local autonomous agents without polluting GitHub or GitLab.
   - Local issue files live under the configured local machine folder, not a global `ai/<machine>/Issues/` path.

4. **GitHub and GitLab tab behavior**
   - Fetch fresh issue state from the API when the Issues viewer opens, refreshes, or switches to the remote tab.
   - Interactions with GitHub/GitLab issues use the API, not local markdown storage.
   - These tabs are for shared/big-picture/project-level issue tracking and delegation.

5. **Other machine tab behavior**
   - Scan sibling folders under `ai/` for `Issues/` folders.
   - Show a tab for each discovered non-local machine with issues.
   - These tabs expose repo-synced local issue folders from other machines for inspection and coordination.
   - Do not automatically ingest other machine tickets into the local machine's active workflow unless an explicit pull/ingest action or hook does so.

6. **Cross-machine ticket handoff flow**
   - A user or machine can add tickets to another machine's `ai/<machine>/Issues/` folder and push them.
   - A GitHub/GitLab ticket can tell the target machine to pull those tickets.
   - A hook on the target machine can see that remote ticket, pull the repo, ingest its local machine tickets, and start executing them.

7. **Board UX still needs redesign**
   - Keep the useful redesign goals: source tabs, columns, create ticket, detail panel, archive/templates, priority, labels, assignee, search, and filters.
   - The redesign should be source-aware: Local/GitHub/GitLab/other-machine tickets may have different allowed actions.

## Files That Will Likely Change

- Issues viewer client components and state.
- Server issue source/discovery APIs.
- GitHub/GitLab issue connector code.
- Local issue filesystem paths under `ai/<local-machine>/Issues/`.
- Cross-machine issue folder discovery under sibling `ai/<machine>/Issues/` folders.
- Existing `ai/<machine>/Issues/` path consumers during migration.
