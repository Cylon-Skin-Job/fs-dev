Define and implement a reliable first-run detection mechanism for Fusion Studio.

### Problem

The app needs to know whether it has been launched before on this machine to decide:
- Copy bundled `System Files` seed to `~/Fusion Studio/System Files/`
- Show onboarding tickets in Issues viewer
- Prompt for cloud backup setup
- Create a default workspace
- Display first-launch welcome / tutorial

### Proposed Approach

**Primary signal:** Check if `~/Fusion Studio/System Files/` exists.
- **Exists** → not first run. Skip seed copy. Load existing templates.
- **Missing** → first run. Execute full onboarding sequence.

**Secondary signal (app-level flag):** `~/Library/Application Support/Fusion Studio/first-run.json`
```json
{
  "first_run_complete": true,
  "first_run_date": "2026-05-19T14:47:01-07:00",
  "onboarding_tickets_shown": true,
  "cloud_backup_prompt_shown": true,
  "default_workspace_created": "~/projects/fusion-studio-default"
}
```

Why two signals?
- `System Files` existence = user-facing state. If the user deletes `~/Fusion Studio/`, we should probably re-run onboarding.
- `first-run.json` = app bookkeeping. Tracks which onboarding steps were completed even if System Files is later deleted.

### Onboarding Sequence (first run only)

1. Create `~/Fusion Studio/System Files/` from bundled seed
2. Create `~/Library/Application Support/Fusion Studio/first-run.json`
3. Inject onboarding tickets into Issues viewer (RCC-0072)
4. Show cloud backup prompt (optional — user can skip)
5. Prompt user to choose or create first workspace
6. Mark `first_run_complete: true`

### Edge Cases

- **User deletes `~/Fusion Studio/` but app data remains:** Re-copy System Files on next launch, but don't re-show onboarding tickets if `first_run_complete: true`.
- **User deletes app and reinstalls:** `first-run.json` is gone → treat as first run. But if `~/Fusion Studio/` still exists from prior install, merge new seed templates instead of overwriting.
- **Multiple macOS users:** Each user has their own `~/Fusion Studio/` and `~/Library/Application Support/Fusion Studio/` — first-run is per-user, which is correct.

### Open Questions

- Should first-run detection be per-workspace or global to the app?
- If user deletes `~/Fusion Studio/` manually, should we ask "Looks like this is your first time" again, or silently re-create?
- Should onboarding tickets persist after completion, or auto-archive?
