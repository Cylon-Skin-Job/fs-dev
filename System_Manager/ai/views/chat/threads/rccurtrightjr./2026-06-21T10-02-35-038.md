**Possible Expanded Skill Skeleton**
```md
## Guidance

Use this skill when evaluating completed or proposed work for correctness, regressions, risk, and missing validation.

Review workflow:
1. Identify the review scope and expected behavior.
2. Inspect relevant code, tickets, specs, docs, tests, or evidence.
3. Compare implementation against requirements and project patterns.
4. Report findings first, ordered by severity.
5. If no findings are found, state that clearly and list residual risks.

Finding format:
- Severity: Critical | High | Medium | Low
- Reference: file path, ticket, spec section, evidence card, or wiki page
- Issue: what is wrong or risky
- Impact: why it matters
- Recommendation: smallest practical fix or validation step

Rules:
- Do not rewrite or fix reviewed work unless explicitly asked.
- Prefer concrete evidence over speculation.
- Call out missing tests, unclear requirements, and unverified assumptions.
- Keep summaries secondary to findings.
```

Main recommendation: make the skill more procedural and enforce a repeatable output format. That will make reviews much more consistent.
