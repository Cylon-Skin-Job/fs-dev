Build the engine that copies bundled System Files seed to the user's home on first run, then merges updates (add new templates, preserve user customizations).

**Roadmap:** `ai/<machine>/Views/*-doc-viewer/specs/ROADMAP-REVISED.md` Phase 2.10
**Depends on:** Chunk B (filesystem restructure — complete)
**Blocked by:** —

---

## What Needs to Happen

1. **Write the spec** — `ai/<machine>/Views/*-doc-viewer/specs/chunks/chunk-G-system-files-engine.md`

2. **First-run seed copy**
   - Detect first run (check if `~/Fusion Studio/System Files/` exists)
   - Copy bundled seed templates to user home
   - Create `~/Library/Application Support/Fusion Studio/first-run.json` for bookkeeping

3. **Merge engine**
   - On app update: compare bundled seed vs user System Files
   - Add new templates that don't exist in user copy
   - Preserve user customizations (don't overwrite modified files)
   - Track which files are "managed" vs "user-created"

4. **Template instantiation API**
   - `instantiateTemplate(templateId, workspacePath)`
   - Copies a view template from System Files into a workspace's `ai/<machine>/Views/`
   - Auto-numbers view IDs: `wiki-viewer-01`, `wiki-viewer-02`

5. **Template discovery on boot**
   - Scan `System Files/views/` for available templates
   - Expose list to client for "Add View" context menu
