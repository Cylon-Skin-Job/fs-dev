Built-in Issues Viewer remains a React view. This ticket previously described converting the built-in view to an iframe; that direction is superseded. Redesign the existing React surface instead of creating `ai/<machine>/Issues/app/` as a built-in iframe.

**Roadmap:** `ai/<machine>/Views/*-doc-viewer/specs/ROADMAP-REVISED.md` Phase 4.1
**Depends on:** Current React view architecture and issue data routes
**Blocked by:** none known

---

## What Needs to Happen

1. **Review existing spec** — `ai/<machine>/Views/*-doc-viewer/specs/chunks/chunk-J-issues-viewer.md`
   - Use it for product behavior only; ignore implementation details about converting built-ins to iframes

2. **Redesign the React view**
   - Keep Issues Viewer as a built-in renderer surface
   - Split large React components into focused components, hooks, and services as needed
   - Do not add `ai/<machine>/Issues/app/` for the built-in Issues Viewer

3. **Renderer data flow**
   - Use the existing renderer store/service and WebSocket paths
   - Do not use postMessage or a theme-token iframe bridge for this built-in view

4. **Full feature set (do not port current TicketBoard)**
   - Three columns: Inbox / Open / Completed
   - Create ticket modal with full fields
   - Ticket detail panel (replaces current broken overlay)
   - Archive drawer with templates tab
   - Priority, labels, assignee switching
   - Search + filter

5. **File-change events**
   - Listen for `file:changed` UEB events via WebSocket
   - Refresh board when `tickets.json` changes
