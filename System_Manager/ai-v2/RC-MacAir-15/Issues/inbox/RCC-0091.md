First view migrated from React to a self-contained HTML/CSS/JS iframe. Establishes the view convention for all subsequent migrations. Full Issues-viewer redesign — not a port of the current TicketBoard.

**Roadmap:** `ai/views/doc-viewer/specs/ROADMAP-REVISED.md` Phase 4.1
**Depends on:** Chunk D (iframe view loader), Chunk E (theme token bridge — D complete, E pending)
**Blocked by:** Chunk E

---

## What Needs to Happen

1. **Read existing spec** — `ai/views/doc-viewer/specs/chunks/chunk-J-issues-viewer.md`
   - Already written; use it as the implementation guide

2. **Build the iframe view** in `ai/views/issues-viewer/app/`
   ```
   app/
   ├── index.html       ← thin shell: mounts #app, loads app.js
   ├── app.js           ← entry point: initializes modules, handles postMessage
   ├── style.css        ← structural layout only (no hardcoded colors)
   ├── board/           ← column rendering, card events
   ├── drawer/          ← slideout drawer: archive + templates tabs
   ├── detail/          ← ticket detail panel: fields + comments
   ├── create/          ← create ticket modal
   └── state/
       └── store.js     ← module-level state
   ```

3. **postMessage protocol**
   - On load: `view:ready` → shell responds with `theme:tokens`
   - View validates `e.origin === 'fusion-studio://'`
   - View writes tokens to `:root` CSS custom properties

4. **Full feature set (do not port current TicketBoard)**
   - Three columns: Inbox / Open / Completed
   - Create ticket modal with full fields
   - Ticket detail panel (replaces current broken overlay)
   - Archive drawer with templates tab
   - Priority, labels, assignee switching
   - Search + filter

5. **File-change events**
   - Listen for `file:changed` UEB events via WebSocket
   - Refresh board when `tickets.json` changes
