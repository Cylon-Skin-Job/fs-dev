## Workspace Creation Modal

Two options presented as vertical radio buttons:

```
┌─────────────────────────────────────┐
│  Create Workspace                   │
│                                     │
│  ○ Create from Project Folder       │
│    (select an existing folder)      │
│                                     │
│  ○ Create New Workspace             │
│    (name: [________________])       │
│                                     │
│           [Cancel]  [OK]            │
└─────────────────────────────────────┘
```

**Option 1 — Create from Project Folder:**
- Opens macOS system file picker
- User selects existing project folder
- Fusion Studio creates `ai/` inside it
- Preserves all existing project files

**Option 2 — Create New Workspace:**
- Text input for workspace name
- Creates new folder at `~/projects/{name}/`
- Populates with default structure

## Default Workspace Structure

On creation, every workspace gets:

```
{workspace}/
├── ai/
│   ├── system/           # state.json, theme.json, data/
│   │   └── data/         # workspace.db, solobooks.db
│   ├── chat/             # chat threads
│   └── views/            # view instances
│       ├── file-viewer-01/
│       ├── issues-01/
│       ├── wiki-01/
│       └── tools-01/
└── (existing project files, if Option 1)
```

**Default views (auto-created):**
| View | ID | Purpose |
|------|-----|---------|
| File Explorer | `file-viewer-01` | Browse project files |
| Issues | `issues-01` | Track tickets |
| Wiki | `wiki-01` | Documentation |
| Tools | `tools-01` | Skills, triggers, scripts, hooks |

**Optional default (System Files template):**
| View | ID | Purpose |
|------|-----|---------|
| Doc Viewer | `doc-viewer-01` | Capture folder, specs, notes |

## System Files Template Library

`System Files/views/` ships with templates for all view types. Bare minimum bundled:

**Core (always available):**
- `file-viewer/` — File explorer
- `issues-viewer/` — Ticket board
- `wiki-viewer/` — Documentation
- `tools-viewer/` — Skills, triggers, scripts, hooks (was agents)
- `doc-viewer/` — Notes, captures, specs

**Optional (add via "Add View"):**
- `browser-viewer/` — Embedded web browser
- `terminal-viewer/` — Terminal/shell
- `calendar-viewer/` — Reads from global `fusion.db` calendar table
- `email-viewer/` — Reads from global `fusion.db` email table
- `spending-viewer/` — Solobooks, per-workspace SQLite
- `library-viewer/` — JSON library, media assets
- `office-viewer/` — Office apps grid, per-workspace storage
- `media-studio/` — Video/audio editor (Phase 5)

**Global views** (read from central system DB, can be added to any workspace):
- Calendar, Email, Reminders, Photos

**Per-workspace views** (data lives in workspace only):
- Spending, Office, Library, Media Studio

## Office Viewer: Per-Repo + Symlink Sync

Office viewer data lives in the workspace:
```
{workspace}/ai/system/data/office.db
```

If user wants shared office data across multiple workspaces:
- Create office view in Workspace A
- In Workspace B, create office view + symlink its data folder to Workspace A's
- `ln -s ~/projects/workspace-a/ai/system/data/office ~/projects/workspace-b/ai/system/data/office`
- No built-in sync — symlinks are the mechanism

## AI Onboarding Prompt

After workspace creation, AI auto-injects a prompt via ticket registry (RCC-0074):

> "Welcome to your new workspace. I've set up the basics — file explorer, issues, wiki, and tools. What else do you need?
>
> • Is this a **research library**? I can add the JSON viewer and arXiv scraper.
> • Need **automations**? I can set up contextual RAG embedding enrichment.
> • Want a **vector database** for semantic search? I can add `vectra` or `chromadb` next to your SQLite in `ai/data/`.
> • Just exploring? Ask me anything."

The AI offers to add views, configure automations, or explain the folder structure. User can dismiss and never see it again.

## Vector Database (Future)

Optional add-on for RAG/semantic search:
- Stored in `ai/data/vector.db` (or separate folder)
- Indexes workspace documents, wiki pages, chat history
- AI can query for contextual relevance
- Not part of default workspace — added on request
