## What Needs to Happen

1. **Write the spec** — `ai/views/doc-viewer/specs/chunks/chunk-E-theme-token-bridge.md`
   - Shell reads `ai/system/styles/themes.json` + slider values
   - Computes CSS custom property tokens (colors, spacing, typography, shadows)
   - Broadcasts tokens to all warm iframes via `postMessage`
   - View iframes validate `event.origin === 'fusion-studio://'` before accepting tokens
   - View writes received tokens to `:root` CSS custom properties

2. **Shell-side implementation**
   - Hook or utility in the renderer that reads the active theme and computes tokens
   - `postMessage` broadcast to every `.rv-view-iframe` on theme change / workspace switch
   - Tokens should be sent as a structured object, not a raw CSS string

3. **View-side contract**
   - Document the expected `postMessage` payload shape for view authors
   - Provide a minimal reference implementation (e.g. a small JS snippet views can copy)

---

## Key Decisions Already Resolved

- `fusion-studio://` protocol is registered with `secure: true` and `standard: true` — `event.origin` in the iframe will be exactly `'fusion-studio://'`
- Warm iframes are already in the DOM; broadcasting means iterating `document.querySelectorAll('.rv-view-iframe')`
- `postMessage` targetOrigin can be `*` because the iframe `src` is shell-controlled and the view validates origin on receipt
